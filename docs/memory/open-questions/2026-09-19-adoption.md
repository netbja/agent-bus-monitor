# What remains to verify before claiming shared-memory adoption

## Questions

- Have the structure and boot/handoff references been integrated together?
- Can a fresh Claude, Codex, Kimi or Grok session locate this index, explain the
  PEL lesson, and add a sourced correction without relying on private history?
- Which clients actually load AGENTS.md automatically, and which need an explicit
  role/bootstrap instruction? Has a running session reread changed instructions?
- Which commit of the reference is available on laptop and VDR? Has the human
  opened the canonical memory folder in Obsidian, without a duplicate copy?
- Which other project's owner wants to expose a canonical index? Which historical
  brain lessons should be promoted after checking their sources and scope?
- Has the separate test-endpoint safeguard been validated and integrated? Never
  infer that from this memory branch.

## Evidence and decision process

[The access protocol](../ACCESS.md) defines what can be claimed. Run structural
checks and a fresh-context read/write exercise; record the participating clients,
source revision and actual outcomes. Mark individual questions resolved with that
evidence instead of changing all of them to done because files were created.

## Limits

These are adoption questions, not a second board of operational tasks. Live
backlog handling and deployment remain separately authorized operator decisions.
No acceptance, approval or runtime status is inferred from this checklist.
