# v0.8.0 — event-driven dispatch

An idle agent can now stay **disconnected at zero token cost** and still be reached. A task
published for it wakes it, its answer wakes the requester the same way, and no LLM takes part
in ordinary routing. Without a running dispatcher, everything behaves as in v0.7.

## What changes

- **`agentbus dispatch`** — a deterministic process, one per project (a second exits 0). It
  watches `{project}:cmd`; when an entry waits for an agent that is **not armed**, it types one
  fixed line into the agent's herdr pane and never the message itself:
  `[agentbus#<nonce>] <project>: <n> message(s) waiting for <agent>. Run: agentbus --project <project> subscribe --drain <agent>`.
  Options: `--horizon 24h`, `--escalate-after 10m`, `--escalate-to master`. One JSON decision
  line per change on stderr. `agentbus dispatch --status` prints `dispatch up` (exit 0) or
  `dispatch down` (exit 1).
- **Readiness before typing.** herdr state `idle`/`done`; no client busy signature (herdr's own
  state is not trusted alone); a visible empty input line on a settled screen; the pane **not
  focused**; and the pane's foreground process matching the pid + start time the agent recorded
  with its last `agentbus status`. Signatures ship for Claude Code, Codex, Kimi, Grok and
  Antigravity (`agy`), from the probes in the spec (§10); any other client is never prompted.
- **Bounded wakes.** At most one prompt per agent per 60 s and three per backlog, enforced in
  Redis across dispatcher restarts. Otherwise the agent is deferred; after `--escalate-after`
  (4× for an agent herdr reports `working`), or after three wakes without progress, an
  `escalation` cmd goes to `--escalate-to` plus a `notify`. If the stuck agent is the recipient,
  only the `notify` is sent.
- **`subscribe --drain <agent>`** — empties the agent's queue (pending entries, then unread, no
  floor, ACK after output) as one JSON object per entry, then exits 0 (output), 64 (empty) or 75
  (error, e.g. the receiver lease is held). A woken agent must drain: a plain `subscribe` floors
  at "now" and acknowledges the waiting entries unseen.
- **Additive protocol changes** (`ProtocolVersion` stays 1):
  - cmd field `wake=no` (`agentbus cmd --no-wake`): delivered, never wakes. `shutdown` uses it.
  - cmd types `escalation` (dispatcher → recipient) and `blocked` (`request block` → the
    requester, only on a transition or a new reason).
  - drain/subscribe fields `stale` (entry older than the 24h horizon) and `age_s`. A stale entry
    never triggers a wake on its own and must not be acted on without confirmation.
  - keys `{p}:dispatch` (dispatcher lease, `PX 15000`, renewed every 5 s; counts as a project
    key) and `{p}:wake:{agent}` (per-agent wake record).
  - `AgentSnapshot` gains `pid`, `pid_start`, `terminal`, recorded by `agentbus status` inside
    herdr. Snapshots without them (older binaries, outside herdr) are never prompted.
  - An agent's cmd consumer group is created at `now − 24h` by `agentbus status` (and by the
    dispatcher), so a command sent shortly before an agent registers is still captured.
- **Fenced writes.** Every dispatcher write — wake records, escalation and notify entries,
  deletes, group creation — runs in Lua behind a check of the lease token, so a dispatcher that
  lost its lease, or whose project was deleted, writes nothing and recreates no key.
- **busmon** — STATUS bar `dispatch ●` / `dispatch ○`; agent chips `✉N` (messages waiting, no
  wake under way), `⏰` (wake in flight or deferred), `⚠` (escalated), `old:N` (entries past the
  horizon), `✂?` (entries may have been trimmed before the agent's group read them).
- **bootstrap** — the generated template gains a `dispatch` tab running
  `<repo>/agentbus --project <p> dispatch`, next to the `busmon` tab; `--no-dispatch` omits it.
  Bootstrap still only writes the template; the human opens the workspace.
- **Skills and rules.** `agent-bus`: on a `[agentbus#` line, drain first, never a plain
  `subscribe`; don't re-arm only to wait for an answer while `dispatch up`; never act on a stale
  entry unconfirmed. `agent-bus-master`: may sleep only while `dispatch --status` reports up;
  otherwise the v0.7 armed rule stands; manual pane wake is the fallback; `escalation` and
  `blocked` explained. `agent-bus-sentinel`: every cron wake runs `dispatch --status` and
  notifies the human when it is down. `CLAUDE.md` replaces "don't reintroduce a pane-relay /
  watcher daemon" with: *the only automated process that types into panes is `agentbus
  dispatch`, and it types a wake line, never a message; master's manual pane injection remains
  the fallback while no dispatcher runs* — recorded as a
  [decision note](../memory/decisions/2026-10-10-event-driven-dispatch.md).

## Use it

Build `agentbus` in the repository (`go build -o agentbus ./cmd/agentbus`; the dispatch tab
runs `<repo>/agentbus`) and regenerate the project template with `scripts/bootstrap new <p>` to
get the tab, or run `agentbus --project <p> dispatch` in any pane on the host running herdr.
Agents must publish `agentbus status` from a binary of this version, inside their herdr pane,
before the dispatcher can wake them. Design: the
[spec](../superpowers/specs/2026-10-10-event-driven-dispatch-design.md) and
[plan](../superpowers/plans/2026-10-10-event-driven-dispatch.md).

## Live acceptance — pending

Not yet run. It is planned on an isolated Redis, with an `agentbus` built from this branch
(revision and `agentbus version` recorded), project `v08-accept`, and panes for Codex, Kimi,
Grok, Antigravity (and Claude Code where supported), each running `agentbus status <name> idle`
once and then left unarmed, with `agentbus dispatch` running. The checks:

- (a) `request send` to each agent → exactly one prompt each in the dispatch log, then drain,
  `accept`, `done`; publish→prompt latency recorded.
- (b) Requester asleep → woken by the reply.
- (c) A focused peer pane → no prompt; `⏰`, then `⚠` with `--escalate-after 1m`.
- (d) Text typed in a peer's input line → wake deferred.
- (e) 30 minutes idle: zero prompts in the dispatch log, herdr state `idle` for every pane
  (sampled each minute), and token evidence where the client exposes it (Claude transcript usage
  lines, Codex session files); for clients that expose none, that is stated rather than inferred.

Results will be added here; until then, no live behaviour is claimed.

## Limits

- Delivery is guaranteed, execution is not: a crash after ACK and before `request accept` is not
  replayed (unchanged from v0.7).
- Entries trimmed by the ~1000-entry cap before an agent's group read them are lost to that agent;
  busmon shows `✂?` and the dispatcher sends one `notify`, but the loss cannot be counted.
- Accepted residuals: a dispatcher suspended between its token check and the herdr call can emit
  one extra prompt (it costs one short, empty turn); `busmon --delete` while a dispatcher runs can
  orphan one fenced write; a focus switch inside the inspect→prompt gap is not caught.
- The dispatcher and herdr must run on the same host (process identity is read from `/proc`).
- Client screen signatures follow client releases and will need re-probing; a client whose screen
  stops matching is deferred and escalated rather than prompted.
- `report` and `notify` never wake anyone; only `{project}:cmd` does.
