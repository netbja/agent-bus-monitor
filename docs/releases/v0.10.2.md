# v0.10.2 — the operator is a person; no more Python

Two things land in this release.

The person at busmon is shown as a person. Before, busmon wrote as the historical agent name
`hermes`, and a message typed with no `@` was a broadcast that no agent read. Now busmon shows
who you are, `@all` reaches every agent, and a broadcast no longer looks like a chat.

The role launcher, which was still Python, is now Go. It ran as the first real missions change.

## The operator is a person (busmon)

- **Who you are.** `busmon --as bernard`, or `AGENT_BUS_HUMAN`, sets your name on the bus. With
  no name you are `pilot`, and there is no other default (`hermes` is gone).
  - The header shows **`♙ Bernard [human · pilot]`**. `pilot` appears only while you hold the
    pilot lease. With no name, it shows `♙ Pilot [human]`.
  - Activity shows `♙` and the capitalised name on every entry a person wrote, in every busmon
    watching the project.
- **Marked on the bus.** `Bus.HumanCmd` and `Bus.HumanNotify` add `human=yes` to the entry.
  `subscribe` and `subscribe --drain` give agents `"human": true`, an additive field within
  protocol `v1`. The peer skill tells agents to act on a human directive first and to answer on
  the bus.
- **`@all <text>`** sends a directive to every agent the project knows, and the dispatcher wakes
  each one. Footer: `directive sent to N agents`.
- **No silent broadcast.** Plain text is a `notify`: no agent reads it and nothing wakes for it.
  This is why a test message got no answer. The first Enter now says
  `nobody reads a broadcast: start with @agent or @all; Enter again to broadcast`, and a second
  Enter sends it.
- Help, placeholder and README say the same.

## Role launcher in Go (`agentbus roles`) — PR #54

- `scripts/lib/role_config.py` and the template generator embedded in `scripts/bootstrap` are
  ported to the package `rolecfg/` and to `agentbus roles
  validate|exists|tier|field|launch|install|template|check-toml`. The command needs no project
  and no broker.
- The scripts call it: `roles.sh`, `agent-launch`, `link-role-skills.sh`, bootstrap's template,
  and `agent-spawn` (which reads herdr's JSON with `sed`).
- `agent-launch` `exec`s `agentbus`. It binds the pane, then `syscall.Exec`s the client, so the pid
  never changes.
- **No Python is required any more.** `install.sh` no longer checks for it, and the Python suite
  is gone. In its place:
  - `tests/roles_scripts_test.sh` covers the scripts end to end;
  - the tests in `rolecfg/` cover the units.
- **Parity.**
  - Before it was deleted, the Python suite passed 13/13 against the Go-backed scripts.
  - Dry runs are byte-identical on 28 role × herdr cases.
  - The adapter spec JSON is byte-identical to Python's `json.dumps`, checked against two goldens
    produced by `role_config.py`.
  - Kimi ran an independent check: PASS on 126 cases.
- **How it was built.** It was the first change run as real missions, on the bus project
  `busdev`: 4 missions, Codex and Claude as agents and as each other's reviewers, and the
  conductor's `complete` signal at the end. The review loop rejected five deliveries, each for a
  real defect, in both directions.

## Upgrade

```bash
git pull && ./install.sh        # rebuilds agentbus and busmon; no Python needed any more
go install ./cmd/...            # if ~/go/bin comes first on PATH
busmon --project <p> --as <your-name>
```

not used.

  `agentbus mem check` pass.
- New tests cover:
  - the identity (flag, environment, default, invalid name) and the label;
  - the header with and without the lease, and the Activity sender;
  - `@all` reaching every agent;
  - the broadcast confirmation;
