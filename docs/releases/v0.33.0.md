# v0.33.0 — busmon for several projects, ideas triage, broker hardening (off by default), and the first steps of person memory

This release gathers the PRs merged into `dev` since v0.32.0, #683 to #719 (35 of them; #685 and
#699 were closed and replaced). `dev` stood at `b9dcb27c` when they were written. `main` takes them as one
promotion, on the person's yes. These notes are their own PR.

**Nothing in this release changes the live broker.** The broker's new durability settings and the
per-role ACL users take effect only when the person acts: recreating the broker, or turning
`broker.acl` on, which defaults to `off` and which no installer step can yet turn on. Upgrading
leaves the broker, its password and every agent's access as they were.

**busmon: working across projects** (#705, #706, #714, #717; notes `project-switch-ux`,
`explain-unknowns`, `other-projects`):

- **Back, and a stopped project** (#705). `B` returns to the project a switch left. A project
  reached by a switch whose dispatch does not run shows a banner under the header, "stopped
  project · read-only", with `S`, `M` and `B`. `S` runs `agentbus service start` (dispatch, then
  missions; the agents stay down) after a `y`, as the person only. While the banner shows, every
  write is refused with "stopped project: read-only, S starts services"; it lifts as soon as
  dispatch runs. `o` alone still starts nothing.
- **The header counts the other projects** (#714): `other: N for you · M merge (O)`, summed over
  this broker's other projects, shown only when something waits. N is the for-you rows other than
  merges, M the merges waiting. It reads every 2 minutes, 4 projects at a time, read-only, and
  only projects whose dispatch holds its lease; a failed or stale read drops out, never counts as
  0. `O` opens the project with the most for-you rows, through the same checked switch, so `B`
  comes back.
- **busmon says why something is unknown** (#706). When the dispatcher does not run, For you's
  merge line reads "merge queue unknown: <why>", the header's health summary adds the reason after
  `?N`, and the quota gauges get one "(<why>)" when a provider has no reading: "project stopped",
  or "dispatch down", "dispatch failed", "dispatch gave-up".
- **The read-only guard covers the notification set-up** (#717): the write, remove and rename of
  `notify.toml` and `config.toml`'s `notify.*`, and the palette's follow. A refused write leaves
  the set-up's step as it was.

**busmon: ideas, the Plan, Tokens and settings** (#684, #690, #695, #697, #702, #703, #713):

- **Ideas have a fifth state, `later`** (#697): kept for another time, between doing and dropped
  (`agentbus idea set <id> later`, F6's picker and filter). Each F6 row says its state in its
  colour, and an idea's text wraps instead of being cut. An older `agentbus` or busmon lists a
  `later` idea under no section and refuses `later`: update both on every host that triages.
- **One key per state** (#713). On the Ideas list and an idea's page, `y` decided, `l` later,
  `d` doing, `x` dropped, at once and as the person (the `s` picker stays and has the same
  refusals). `u` undoes this busmon's last change once. `Y` copies the whole idea there; `y`
  still copies on every other page, and `l` stays the Services page's log.
- **The Plan, after the person's two reviews** (#684, #690). `p` opens the drawer under a For you
  of its own rows. The board has one header line and a rule, expands only the groups with open
  tasks (each finished group is one line, `▶ N groups done · M tasks`), has no blank lines, aligned
  columns (glyph, title, owner, state, age), and a strip under a rule with the selected task's
  detail. Bars and state words take the state's colour (orange waits for the person, blue in
  progress or review, green approved, grey done, red blocked).
- **The Tokens page (U)** (#695). Each project's 7-day sparkline is 14 cells scaled to its own
  busiest day, the right-hand number is the seven days' in+out, the in/out columns are today's,
  and bar rows are one line with a blank line between them. A finer resolution would need a bus
  change, which waits for the person.
- **`person.language` is chosen from a list** (#702). Enter on "Your language" in the settings
  page opens the ISO 639-1 table (`fr  Français (French)`); typing filters it, and only a list
  entry can be written. `agentbus config set` and a hand edit are still judged by the key's own
  rule. Any setting given `Options` in `config/keys.go` gets the same list.
- **`busmon --delete` keeps the Projects page's rules** (#703). A project that is not asleep is
  refused, `--yes` included (an unknown counts as live); the hosts where its units remain are named
  before the question and after the delete; a backup is taken just before, and a failed backup
  deletes nothing. The archive is never removed by `projects.delete_backups`.

**Background work** (#693, #696; note `bg-mcp-helpers`):

- **A client's own MCP servers and daemons are not background work** (#693). A client profile may
  declare `direct_helpers = true` under `[background]`: the client's direct children that are not
  a shell are its helpers, and never count, whatever their CPU. Claude Code declares it. Work the
  agent starts runs under the client's shell, so a dev server it left still blocks `auto-clear`
  and `pop-retire`. This ends a real false positive: docs's `pop-retire` skipped for 2 hours on
  `codebase-memory`.
- **A helper's whole subtree is the helper's** (#696): the `node` an `npx`-started server runs and
  codegraph's watcher no longer count. For Codex the helpers are listed by name
  (`helper_branches`), because a one-command `bash -c` execs the program in place. Codegraph under
  Codex is still counted. Grok, Kimi and agy are not checked.

**Broker hardening — stated, and off by default** (#688, #689, #691, #701, #707, #709 to #712,
#715, #718; spec `docs/superpowers/specs/2026-11-21-broker-hardening-design.md`):

- **Durability is stated** (#689): `docker-compose.yml` gives the broker `appendonly yes`,
  `appendfsync everysec` (a crash loses about a second of writes) and `save 3600 1 300 100 60
  10000` in its config, not Redis's defaults. `broker-persistence` also warns when AOF runs with
  `appendfsync no`. A running broker keeps its old settings until the person recreates it.
- **The stated limit** (#688). Agents run as the person's OS user, so they can read the
  credentials the person's files hold. ACL users protect against mistakes, not a hostile agent.
- **The broker's runtime is a setting** (#691): `broker.runtime` is `docker` or `podman`, and the
  installer, the health checks, busmon's Redis page and `scripts/bootstrap` follow it. `broker.image`
  names the image, and a backup records the server (`redis` or `valkey`); a restore across them is
  refused. Not verified: the Valkey image's tool names and the `redis-version` check on Valkey.
- **ACL users per role, behind `broker.acl`** (#701, #707, #709 to #712, #715, #718). `bus.ACLRules`
  holds the proposed users, and a test replays every command the suite's callers send through
  `ACL DRYRUN` (#701). Four answers of the person made writes master's: an agent's request no
  longer writes the run or the plan (#707), master's `retire --forget` needs no right on the
  dispatch lease (#709), `plan load|link|done|note|ignore|clear` refuse another agent (#710),
  `mission load|retry|skip|reassign|abort` likewise (#711), and `merge-queue drop` and `undrop` are
  master's, docs included (#712). docs's plan link after a delivery becomes a directive to master.
  With `broker.acl=on`, each process logs in as its role's user from
  `~/.config/agentbus/redis-<user>.env`, and a missing file is an error, never the default user
  (#718). **It is `off` by default and nothing turns it on yet**: `./setup.sh acl on|off`, which
  creates the users and files, and the per-user rotation are still to build, so leave it `off`.
  Until it is on, the refusals above are a courtesy message, not a barrier.

**Person memory, steps 1 and 2** (#704, #716; spec `2026-11-21-person-memory-design`):

- **`typed=yes` marks what the person typed** (#704): busmon's directives and broadcasts and an
  ask's answer, which also carries `said` (the chosen label or the free text alone). `human=yes`
  alone means "written in the person's name" (a resume summary, a close). The `subscribe` JSON
  says `"typed": true`, additively within v1; entries from before carry `human=yes` only.
- **The person's store** (#716): a `personmem` package keeps one Markdown file per topic in a git
  repository under `${XDG_DATA_HOME:-~/.local/share}/agentbus/memory/person`, directories 0700 and
  files 0600, with checks on the source (typed by the person, quoted), the sensitive fields and
  the bounds. **No command or page uses it yet**: the person sees nothing from it in this release.

**Skills** (#698, #719):

- **Master's reports name items by id** (#698): "what remains for you" lists ids only and is left
  out when nothing new is asked; a report with nothing new for the person is not sent to them.
- **One format for every question to the person** (#719; idea from the Superpowers plugin). A
  question goes through `agentbus ask` with structured options, whatever the client: one decision
  per question, a short title, one or two lines of context, 2 to 4 options each with a one-line
  consequence, one marked recommended, and busmon's last "Other... (type your answer)". busmon
  already renders it, so there is no code change.

**Smaller changes:** the person is never an agent (#686): an entry under the person's
`identity.as` is no agent whatever terminal it names, the dispatcher skips it, busmon drops it and
`agentbus agents` leaves it out; remove a leftover with `agentbus agents forget <person>`. Three flaky
tests fixed: the peer runner's two tests wait for the idle status before stopping the runner (#683), and `TestServiceRunRetriesAFailedEnsure` measures the retry from the failed ensure's return (#692).

**Specs:** conflict-owner (#687), broker hardening (#688, #715), merge conflicts round 4 (#694),
triage de-duplication (#700). None is built here.

**Upgrading:** run `./setup.sh update`. `agentbus update` still refuses a `dev` build, so it is
for the release after this one. Relaunch each Claude Code agent for the `direct_helpers` rule to
apply, and restart the project's dispatch service when setup offers. To get the broker's stated
durability, the person recreates it (`docker compose up -d redis`) when it suits them. Do not set
`broker.acl`.

**Limits:**

- `broker.acl=on` cannot be completed by setup yet. The Valkey and podman paths are checked by tests,
  not on a host.
- The Mac rollback check of `agentbus update` is still open.

**Left out of this release:** the ACL switch in `setup.sh`, per-user password rotation, any command
or page for person memory, the update's automatic mode, and the specs' builds.
