# v0.22.0 — busmon on bubbletea, the context alert, specialist roles

This release gathers everything merged since v0.21.0 (PRs #95 to #135). The launcher change
specified as v0.21.1 (#114) was never tagged on its own and ships here.

**busmon looks different.** It now runs on bubbletea v2 and lipgloss v2 instead of tview (#121-#127,
spec #120). The panels, keys, flags, `busmon.toml` and the local cache are the same. Here is what
you will notice:

- Code in an overlay wraps by grapheme cluster with a muted continuation gutter instead of being
  cut. An exotic emoji cluster that terminals measure differently is shortened to a safe first
  rune.
- `1` to `3` pick a tab at every width.
- Enter on an Activity or For you line expands it in place. A second Enter opens it in the
  reader, a stack of pages; Esc goes back.
- The mouse works:
  - the wheel scrolls three rows without moving the focus;
  - a click selects a row, and a click on the selected row opens it;
  - a click on a scrollbar pages;
  - a tab label or a frame title takes the focus.
- The compose window is a new text area. Its length cap counts characters, never terminal cells.
- The reminder and the header's `for you` badge count asks, waiting agents and open gates, with
  one row per ask.
- `busmon --pick` runs on the same engine and still never provisions.

tview has left `go.mod`.

**Context fill and the alert at 80 %** (#128-#130, decision
`docs/memory/decisions/2026-10-27-context-fill.md`):

- **Where the fill comes from.** `agentbus statusline` records Claude Code's own
  `context_window.used_percentage` per session in `~/.cache/agentbus/context/` (0600). The
  dispatcher publishes it every minute to `{p}:context`, reading only the session bound to the
  agent's verified identity. No reading means unknown, never 0.
- **The alert.** At `AGENT_BUS_CONTEXT_ALERT` % (default 80; `0` turns it off), once per agent and
  session:
  - the agent gets a directive to commit WIP and hand off;
  - the escalation target gets a `wake=no` notice;
  - the desktop gets one `notify-send`.

  There is no alert during a pause, or on an unknown fill or one older than 30 minutes.
- **Where you see it.** busmon shows the fill next to the tokens in the ctx cell (`88k 85%`) and as
  a `Fill` row on the agent page. Health has a new `context` check.

**A pane stuck on its client's prompt rings the desktop** (#133, decision
`docs/memory/decisions/2026-10-27-prompt-notify.md`):

- **When it rings.** A pane busmon flags `prompt` (its client's own menu or permission prompt)
  rings once per episode, after `AGENT_BUS_PROMPT_GRACE` seconds (default 30; `0` turns it off).
- **When it stays quiet.** Not when the agent declared `blocked` or `waiting`, has an open ask, is
  being swapped, or the project is paused.
- **What it touches.** No bus entry, nothing typed.

**Relaunch closes the old pane** (#132, decision
`docs/memory/decisions/2026-10-27-relaunch-close.md`):

- **What is closed.** Once `agentbus up <p>` has proven a relaunched agent (a new live pid bound in
  the new pane, read for up to 60 s), it closes the exact old pane recorded for the dead agent.
- **What is left.** Only a pane that is still a plain shell when re-read just before is closed.
  Anything else is left, with the reason printed.
- **Master's rule.** Master may run `agentbus up agent-bus-monitor --resume` (and its `--dry-run`)
  without a prompt.

**Quota readers for Kimi and agy** (#135):

- **Kimi Code (`moonshot`).** Read from its session logs: a `5-hour` or `weekly` usage-limit hit is
  that window at 100 %. A later answer from the API voids it. Kimi states no reset, so the reset is
  the newest hit plus the window's length, an upper bound.
- **agy (`google`).** Read from its CLI logs: `RESOURCE_EXHAUSTED … Resets in <d>` holds until that
  stated reset. The quota may be per model; `kind = "off"` in `quota.toml` is the escape.
- **What they read.** Only those log files, never a credential or a config.

**The Claude quota stops flapping** (#112). An idle session's status line kept rewriting an old
`7d 95%` with a fresh time, so the dispatcher re-paused the project after every resume. A
status-line reading is now dated by the session's last API answer, and an undated one never wins a
same-reset change.

**The Plan view** (#106, spec #104). `agentbus plan load|link|done|note|show|clear` publishes a
versioned `docs/plans/<name>.json`, together with master's facts. States are derived from the
board, the verdict ledger and asks. A delivered request reads *in review* until it is done.
busmon shows `plan <name> n/m` in the header, the `P` overlay and a Plan section in the recap.

**Specialist roles and the trust gate** (#102, spec #100):

- **Roles.** Six pop roles (`examples/roles.specialists.toml`, prompts in `roles/`); `roles.toml`
  is now schema 2, with profiles.
- **Reviewers.** `agentbus roles reviewers` names models from other providers.
- **Skills.** `setup.sh update` lists changed skills and the roles that use them.
- **Draft and adopt.** `roles draft` and `roles adopt` add a role only after the person's answer.
- **The trust gate.** `agentbus up` starts the first agent of a client that does not trust the
  folder yet alone, and waits for you to answer that client's dialog.

**Other clients and roles:**

- `client = "grok"` is a launcher adapter (#115).
- `ui-grok` and `ui-kimi` are read-only busmon interface advisors (#116, carried to main by #117).
- A profile's permission now wins over the client's own user config:
  - grok always gets `--permission-mode`, `default` included;
  - kimi's `--auto` is announced as elevated (#118).
- **A Claude Code profile must name its permission** (#119). A profile with none, or with
  `"default"`, is refused at load, because `defaultMode` in `~/.claude/settings.json` would decide
  silently. If your private `roles.toml` has such a profile, add one of `acceptEdits`, `auto`,
  `bypassPermissions`, `manual`, `dontAsk` or `plan`.

**Resume through the launcher after a reboot** (#114, spec #97). Every Claude Code launch carries a
`SessionStart` hook. It reports `agent-launch <role> <p> --resume <id>` to herdr's session restore,
so a restored agent keeps its rules and its verified identity. If herdr refuses, the raw
`claude --resume` remains the fallback.

**Sentinel proposes a client reload after an update** (#103, spec #98). The launcher fingerprints
the client it started. The dispatcher notices when the installed client changed and sends sentinel
one directive per update. Health `client-updates` warns, and busmon flags `update`. The reload
itself stays the person's: `/exit`, then `agentbus up <p> --resume`.

**`agentbus help` and short flags** (#96). One table drives `agentbus help [<cmd>]`,
`<cmd> --help` and GNU short flags for both binaries (`-p`, `-H` before the command, the command's
own after it). `busmon -h` is rendered from the same table.

**busmon, smaller changes:**

- **busmon UX** (#101, spec #99):
  - an idle agent whose status names you gets the `for you` flag;
  - the input line and the compose window share one `@` completion;
  - `agentbus report` warns on a long single-paragraph report;
  - entries for you carry ● unread / ○ superseded marks, with a header count and `u` to jump to
    the next.
- A send during a pause asks: resume now, send anyway, or cancel (#110).
- The compose window keeps the cursor in view on a long wrapped line, and has a scrollbar (#109).
- Messages keep their line breaks in threads and in Markdown (#111).

**Tests:**

- The bash suites ignore the inherited `AGENTBUS_BIN`/`ROLES_TOML`, so they test their own build
  (#105).
- The doctor and swap fixtures name a Claude permission, so they no longer depend on the host's
  Claude settings (#131).
- A service-run test joins its goroutine before its temporary directory goes (#134).

**Specs and notes, not built:**

- one dispatcher per host (#113);
- API recovery (#107);
- the skills librarian (#108).

The dogfood-team decision and the v0.21 handoff are recorded too (#95).

## Upgrade

```sh
./setup.sh update
```

What takes effect when:

- **Restart each project's dispatch service** (`agentbus --project <p> service restart dispatch`;
  `setup.sh update` prints the line for each). These features run in it:
  - the context publication and alert;
  - the prompt notification;
  - the Kimi and agy readers;
  - client-update detection;
  - the `context` and `client-updates` health checks.
- **Reopen busmon** to get the new look.
- **Relaunch agents** (`agentbus up <p> --resume`) to get the resume hook, the client fingerprint
  and the permission rules. A running agent keeps its old launch until then.
- **No restart needed for the status line.** The Claude quota fix and the context recording run in
  `agentbus statusline`, which Claude Code starts afresh each time.
