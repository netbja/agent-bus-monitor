# v0.23.0 — what needs you, agents that outlive their context, the installer in Go

This release gathers everything merged since v0.22.0 (PRs #137 to #166). Most of it comes from
Bernard's test of busmon on 2026-10-27: what the screen asks of the person, and what it wastes.

**For you shows only what is yours** (#138, #144, decision
`docs/memory/decisions/2026-10-27-foryou-gates.md`):

- **Gates.** A 4-eyes gate is a For you row, and counts in the badge, only when you opened it or
  it holds you. A review between agents never appears there, and the default `pilot` identity
  never matches. With nothing for you, there is no badge.
- **Verdicts close their gate.** A reviewer's verdict now closes the reviewer's own gate, matched
  by `--ref` or by the subject that `challenge --subject S` records. With `--ref`, it closes that
  gate and the same-subject gates opened before it, never a newer delta's (#144). A self-verdict
  and someone else's verdict close nothing, and a conductor's mission gate is left to the
  conductor.
- **`agentbus gate close`** closes a stale gate without a verdict: `gate close <agent> <ref>
  --note …`, or a sweep by `--subject S`, `--mine` or `--by <name>`, with `--dry-run`. Only the
  challenger may, or a person through an explicit `--as`. It leaves a `wake=no` trace on the
  gate's thread and no ledger entry, so no roll-up changes.

**busmon's look** (#140, #141, #147, #151, #158):

- **Lower tabs in herdr's style.** Each tab is a block with one blank column between tabs; the
  active one is a pill in its panel's colour, dimmed when the panel is not focused.
- **Expanding a line.** Enter on an Activity or For you line shows `▼` in the gutter and the
  text under the message column behind a muted `│` guide, ending with `↵ full text` (and
  `· N more lines` when cut). A second Enter opens the reader, as before.
- **Auto-scroll resumes at the bottom.** Moving the selection onto the newest Activity line, or
  wheeling back to the bottom, turns it back on (`f` and End still do).
- **`n`/`p` in the reader** (or → and ←) show the next or previous item of the list the page
  came from.
- **Smaller fixes.** The Board's task column fits its longest task; the compose window's cursor
  no longer lights the whole row; the health pill reads `health !N`; For you gates get their own
  glyph `◆`; the footer keeps the F-keys last, in order, and always keeps `F1 help` and
  `F5 health`.

**Requests: who owes whom an answer** (#156, spec
`docs/superpowers/specs/2026-10-28-requests-view-design.md`):

- The Requests tab is now one row per thread, grouped by sender, target and kind, in sections:
  owed by you, you wait on, tracked requests, reviews still gated, directives between agents,
  notices.
- A review is owed while its gate is open, never read from its thread. Unread and read come from
  the target's own cursor.
- Answered threads and those older than 24 hours are folded (`o` shows them). Enter expands a
  group or opens a thread, a report notice's report or a request; `d` then `y` closes each thread
  of a group once.

**The Plan tab** (#142): a fourth lower tab beside Activity, Board and Requests, key `4` (the sixth
view in the narrow layout). It lists the loaded plan's tasks as the `P` overlay does; Enter opens
a task or expands done, `y` copies a task. With no plan, it says how to load one.

**Tokens: busmon `U` and `agentbus tokens`** (#159, spec
`docs/superpowers/specs/2026-10-28-tokens-dashboard-design.md`):

- **What is counted.** The dispatch service records each agent's proved session and counts its
  Claude Code transcripts (subagents included) incrementally, per local day, every 5 minutes. A
  request is counted once.
- **`agentbus tokens`** prints every project side by side over 7 days (`--days` 1 to 8),
  `--project <p> --by agent` (today) or `--by day`, `--json`. `--unattributed` scans this host's
  transcripts for what no project's record names. It needs no project: only `--project` on the
  command line narrows it.
- **busmon `U`**: the account windows with a 24-hour sparkline, every project side by side with
  7-day bars, and the open project by agent today. A reading still pending shows a skeleton for
  a while, then `?` with its reason; an agent's `●` pulses only while it declares `working` and
  its pane is seen busy.
- **No cost**, by design: on a subscription the figure would be fiction. An unproved session is
  never `0`.

**F3 Services in three cards** (#160): dispatch, missions and the Redis broker, side by side when
the terminal is wide. A service card shows its state, pid and since when (only for this project's
own service process), a summary, the last error and its log size; the Redis card shows where it
runs, its version, uptime, memory and keys. `↑↓` choose a service card, Enter or `l` opens its
log.

**Every LLM provider in its own colour** (#163): anthropic, openai, google, moonshot, xai,
deepseek and xiaomi each have a colour, used for the header gauges' provider labels, the model
lines of an agent's page and the `U` page. The 16-colour palette uses a hand-picked colour per
provider, and an unknown provider keeps the old colour.

**The first-launch tour** (#155, spec `docs/superpowers/specs/2026-10-28-busmon-onboarding-design.md`):
five pages over the real screen, shown once per machine (a versioned marker in
`~/.cache/agentbus/busmon/_tour.json`, never on the bus). It opens by itself only at a calm
moment and when every page fits whole; F1 then `t` shows it again. Its keys and header pills are
drawn from busmon's own tables, so the tour never names a key that does something else.

**Agents that outlive their context** (#161, #162, spec
`docs/superpowers/specs/2026-10-28-agent-lifecycle-design.md`, decision
`docs/memory/decisions/2026-10-28-agent-lifecycle.md`):

- **The verified session follows `/clear`.** The Claude Code `SessionStart` hook proves the new
  session belongs to the agent's verified process, so a `/clear` no longer leaves the bus reading
  the old transcript. Linux only, like every verified identity.
- **Hand-offs are a record.** `agentbus report` prints its id; `agentbus handoff <self> --report
  <id>` declares that report as the agent's hand-off, and `agentbus handoff` lists them. Any later
  report or non-idle status voids it at once. busmon flags `handoff`; the context alert's
  directive now asks for one.
- **`agentbus reload <role>`** restarts an idle agent on its role and profile, resuming its
  session (`--fresh` starts anew, `--dry-run` changes nothing). It refuses an agent with open
  work (a review, an ask, a mission, an accepted task) and never touches the caller's own pane.
  Sentinel reloads agents after a client update, master only sentinel, and a person anyone with
  `--as <name>`. `agentbus up <p> --reload propose` makes every reload wait for the person,
  `--reload off` leaves them to the person. Reloads are in the swap ledger, and busmon flags
  `reloading`. A shared tool rule denies `reload --as` to every agent role (defence in depth,
  not a boundary).
- **Automatic `/clear`, off by default.** After a declared hand-off, the dispatcher may type the
  literal `/clear` into the agent's pane, once per session, only when every condition holds
  (verified identity, idle since the hand-off, no open question or review, no pause, swap or
  hold, a ready unfocused pane), then proves the new session and tells the agent to read its
  hand-off. `AGENT_BUS_AUTO_CLEAR=1` turns it on; it stays off until its live checks have been
  run.

**The installer in Go, beside setup.sh** (#164, spec
`docs/superpowers/specs/2026-10-28-go-installer-design.md`):

- `scripts/setup-go.sh` checks Git and Go, builds `agentbus` and runs `agentbus setup`, the port
  of `setup.sh` with the same subcommands, flags, questions and output.
- **One addition:** it starts, stops or removes the `agent-bus-redis` container only when that
  container does not exist or belongs to this checkout (its Compose `working_dir` label), read
  again right before each `docker compose` call. A broker started from another copy is reported
  and left alone.
- **`./setup.sh` stays the installer.** This is rollout step 1; the switch comes in its own
  release once the Go port has been tried on real machines.

**Identity and health fixes** (#152, #153, #154):

- **No write as `hermes` from a herdr pane.** Inside a herdr pane without `AGENT_BUS_AGENT`,
  `agentbus` refuses every command that would write as the default sender and says how to fix
  it; read-only commands still run.
- **An agent lost to an identity mismatch rings the desktop** once per episode while messages
  wait for it, since its escalation goes to master.
- **A pop stuck on its client's dialog is named.** A Codex hooks review or a Claude Code trust
  check reads `blocked` from the screen, so busmon flags `prompt` and the desktop rings;
  `agent-spawn` waits for the first status (`AGENT_SPAWN_WAIT`, default 30 s) and otherwise names
  the pane.
- **Health `cmd-delivery`** judges only the consumer groups of agents registered in the project;
  `agents forget` removes a forgotten agent's group.

**Roles:** `reviewer-codex`, a read-only Codex 4-eyes reviewer from another maker (profile
`codex-review`: sandbox `read-only`, approval `on-request`), popped when a second independent
review is needed (#137).

**Docs:** the README and the operational guides (EN and FR) are brought up to date for
everything since the herdr plugin (#166). Plans and specs: #139, #143, #145, #146, #148, #149,
#150, #157, #165.

## Upgrade

```sh
./setup.sh update
```

What takes effect when:

- **Restart each project's dispatch service** (`agentbus --project <p> service restart dispatch`;
  `setup.sh update` prints the line for each). These run in it:
  - the session record and the token counts;
  - hand-off voiding and the automatic `/clear` (when turned on);
  - the identity-mismatch and pane-dialog notifications;
  - the `cmd-delivery` health fix.
- **Reopen busmon** for the new screens, tabs, colours and the tour.
- **Relaunch each agent** for the new tool rules: sentinel's and master's reload rules, the
  shared `reload --as` deny, and master's pop rule for `reviewer-codex`. A running agent keeps its
  old launch, and `agentbus up <p> --resume` leaves a live agent alone (it reads `alive`). So,
  per idle agent, `agentbus --project <p> reload <role> --as <your-name>` (same role and profile,
  its session resumed, launched with the current `roles.toml`); or exit the agent, then
  `agentbus up <p> --resume`. The session proof after `/clear` runs in the installed `agentbus`,
  so it needs only the update.
- **To try the Go installer:** `scripts/setup-go.sh status`, then `scripts/setup-go.sh install
  --dry-run`.
