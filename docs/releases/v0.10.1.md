# v0.10.1 — bound identity, change complete

The v0.10.0 live acceptance found that the dispatcher could never wake Codex, and that master
had no signal when a change was done. This patch fixes both, plus a misleading error message.
Nothing changes for agents the dispatcher could already wake.

## What changes

- **`agentbus bind <agent> [--pane P] [--pid N]`.** Codex 0.162 runs every command through a
  shared `codex app-server` daemon. Its commands are not descendants of its pane, and they inherit
  the daemon's environment, which names another session's pane. So `agentbus status` could never
  record a verified pid, and the dispatcher deferred Codex until it escalated. `bind` records the
  identity instead:
  - the pid must be in the pane's foreground processes, and its start time is read at bind time;
  - without `--pid` it lists those processes (pid, ppid, command) and exits 2, without choosing
    one for you: a wrapper bound by mistake would survive a client restart;
  - the pane comes from `--pane`, or from `HERDR_PANE_ID` inside herdr.

  `bind` works through herdr, so it needs the same access as `herdr pane send-text`. It adds no
  new way to type into a pane.
- **`agent-launch` binds itself.** Inside herdr, the launcher runs `agentbus bind <role> --pid
  <its own pid>` just before it `exec`s the client. Exec keeps the pid and its start time, so the
  bound pid is the client's own, and a restarted client or a recycled pane fails the check again.
  A failed bind prints a warning and the client starts anyway.
- **`status` keeps a verified identity.** Every write of `{p}:agents` goes through one optimistic
  transaction:
  - a status without a pid updates the state and keeps a stored pane and pid;
  - a status that verified itself replaces them, unless a bind was made after its entry (the
    identity carries `ident_ts`, so a delayed status cannot undo a newer bind);
  - an older entry never moves the state back.

  Run with one runtime per agent name.
- **Change complete.** When every mission of the current revision is integrated (skipped missions
  count, reported apart), the conductor runs the change suite once more on the head of
  `change/<change>`. It then sends the escalation target (`master`) one cmd of the new type
  `complete`: `change <c> rev <n> complete on <branch>@<head>: <i> integrated, <s> skipped; open
  the PR to <base>`.
  - The cmd and the `completed_rev` marker are written in one fenced script, so a crash or a
    restart cannot send it twice or lose it.
  - A red suite escalates once per head.
  - A reload to a new revision re-arms the signal.
  - `mission status` shows `complete at <head>`; busmon shows the type in green.
  - The change stays `active`, and the PR to the base is still opened by a person.
- **`mission load`** names the resolved path of a missing brief:
  `brief "brief.md" (resolved: docs/changes/<c>/brief.md) not found`.
- **`agentbus mission` no longer hangs for 10 s.** When its wait for the conductor's answer had
  less than a millisecond left, the read became `XREAD BLOCK 0`, which Redis treats as "wait
  forever", and it ended only at the client's read timeout. Found as a timing-dependent test
  failure under load. It was in v0.10.0 too.
- **Skills.** The master skill handles `complete` and the "no verified identity" escalation
  (`bind`). It wakes a pane by hand with `herdr agent prompt`: in Codex, `send-text` followed by
  Enter left the line unsubmitted.

## Use it

```bash
./install.sh                                       # rebuild agentbus + busmon
agentbus --project <p> bind codex --pane w2:p1     # list the pane's processes
agentbus --project <p> bind codex --pane w2:p1 --pid <client pid>
```

Rebind a hand-started agent after its client restarts. Roles started with `agent-launch` bind
themselves.

## Validation

Disposable Redis via `AGENTBUS_TEST_REDIS_URL=redis://127.0.0.1:6392`; the operational broker was
not used.

- `go build ./...`, `go vet ./...`, `go test ./... -race -count=1` and `bash tests/run.sh` pass.
  The bash tests now unset `HERDR_ENV`, `HERDR_PANE_ID` and `REDIS_URL`, so a run from a herdr
  pane cannot reach the live herdr or broker.
- New tests cover the merge rules, a bind racing 20 concurrent statuses, the bind command (list,
  refuse, record), the launcher (dry run, bind, failed bind), the resolved brief path, and the
  completion cases: sent once across passes and a restart, all skipped, red suite escalated once,
  re-armed by a reload, and an atomic write refused without the lease.
- `bind` was tried against the real Codex pane (the test broker was written, not production): it
  listed the node and native codex processes, refused pid 1, and bound pid 1930926.
- Live, on a throwaway project: after `bind`, the v0.10.1 dispatcher woke Codex on its own
  (`prompt`, 3.7 s). Codex drained the queue and answered on the bus, a loop v0.10.0 could not
  close.
- Design challenged by Codex before coding (spec `docs/superpowers/specs/2026-10-11-v0.10.1-design.md`).
  Codex's final review (APPROVE WITH FIXES) found two issues, both fixed with a test that failed
  first:
  - a delayed verified status could undo a newer bind (identities now carry `ident_ts`);
  - a dirty integration worktree blocked completion silently (it is now escalated once, and
    completion resumes when the tree is clean).

## Limits

- **Reinstall every agent's binary.** An older `agentbus status` still writes the whole snapshot,
  so it erases a bind. Run `./install.sh` (and `go install ./cmd/...` if `~/go/bin` comes first
  on `PATH`) before you rely on `bind`.
- `bind --pid` checks the pid as it is at bind time. A pid recycled in the same pane between the
  listing and the bind would be accepted. The dispatcher's start-time check catches any recycle
  after the bind.
- One runtime per agent name: a second session with the same name shares the bound identity's
  state.
