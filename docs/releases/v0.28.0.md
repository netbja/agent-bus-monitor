# v0.28.0 — stabilisation: the merge queue, one row per report, request priority, and the docs

This release gathers everything merged since v0.27.0 (PRs #309 to #330). It is a stabilisation
release: it fixes how the team stalls and how the person reads it, and it documents what exists. It
adds no new subsystem. What it leaves out is listed at the end.

**What waits for your merge is derived, never written by hand** (#321, spec
`docs/superpowers/specs/2026-11-05-merge-queue-design.md`):

- An open, non-draft PR whose head is the head both reviewers approved is an item of the **merge
  queue**. The dispatch service derives it every 5 minutes from the 4-eyes ledger and the forge, by
  head commit, and caches it. Before, For you listed such a PR only if someone wrote a report or an
  ask about it, and it stopped doing so.
- **busmon's For you** lists each item; Enter opens its page, `y` copies the PR's link (or, with no
  forge, the `git switch` and `git merge` to run), `Y` the reviewers' messages. While a pass fails,
  the rows say `as of HH:MM` and why.
- **`agentbus merge-queue [--json] [--live]`** prints the queue (exit 0 items, 64 none, 2 unknown);
  `--live` derives it now in your checkout and writes nothing.
- Health **`merge-queue`** (for you, never a fail), one `decision` notification per item, and the
  plan: an approved merge task whose subject is queued waits for you.
- GitHub is read through `gh`. GitLab, Bitbucket and GitHub without `gh` fall back to git (a fetch
  that writes no ref). agentbus reads no token.

**busmon reads a report once** (#326, spec `docs/superpowers/specs/2026-11-05-report-one-row-design.md`):

- **One row per report** in Activity and For you: a report and its notice to you fold into one line,
  in either arrival order. A notice whose report is gone keeps its own line.
- **A report's headline** is its first sentence of substance: a leading Markdown heading is skipped,
  so a report starting `## Done` no longer reads as "## Done". The notice, busmon and the `agentbus
  reports` table use it.
- **Read receipt:** opening a report's notice in busmon records that you read it (`{p}:seen`).
  `agentbus reports` shows `read HH:MM` or `unread` for each notice to a person, and `delivered` or
  `pending` for an agent. `agentbus reports --unread [--to <person>]` lists the ones you have not
  opened, so master can see whether you read a report.

**Request priority, phase 1** (#314, spec `docs/superpowers/specs/2026-11-04-request-priority-design.md`):

- A tracked request is **high, normal or low** (normal by default). Only you set it:
  `agentbus request priority <task> high|normal|low --as <your-name>`, or `+` / `-` on its row or page
  in busmon. An agent is refused, and every role denies the command.
- **`agentbus request next [<agent>]`** names the request to take next: one already accepted first,
  then by priority, then by age (exit 64 when nothing is ready). The skills tell agents to follow it.
- busmon's Requests tab marks each tracked request (`↑` high, `↓` low) and sorts by priority.

**The team stalls less, and says so** (#310, #325):

- Health **`review-queue`** (#310, spec `docs/superpowers/specs/2026-11-04-review-queue-design.md`)
  warns, and wakes master once, when the whole team idles while a review is owed: a gate its
  reviewer read and left open past `dispatch.stall_after`, or a subject one reviewer approved and
  another, who reviewed it before, has not approved on the deciding head (within 72 h). It never
  fails, so it never wakes sentinel. It closes the hole that left the team idle about 13 hours on
  2026-11-04.
- **An answered `waiting` counts as idle** (#325, spec
  `docs/superpowers/specs/2026-11-06-stale-waiting-design.md`). An agent's declared `waiting` used to
  stay after you answered all its questions, and `team-stall` and `review-queue` read it as "the
  person decides", so nobody was woken. Now a wait with no open question, answered by you after the
  declaration, counts as idle since your answer, for the stall guards, the notifications and busmon.
  Nothing is written for the agent. reviewer-codex's role also says never to end a turn without a
  verdict per open challenge.

**busmon:**

- **`r` replies** (#311, #324) on a message, report or note page: it opens the compose window to the
  sender, prefilled `re: <first line>`. A report notice quotes its report, never the envelope. It is
  offered only for a registered agent, and an existing draft is kept. On an agent's page, `r` opens
  the compose window to that agent, with no prefill. `i` and `I` still do the
  same; `r` keeps its other meanings where a page offers them (About's replay).
- **About and settings, trimmed** (#323): About drops the author line and the project row under the
  subtitle (the project stays in what `y` copies; the licence line at the foot stays). The settings
  page `C` gets a blank row of top margin.
- The first-launch tour shows its changed page once more ("Useful keys", with the priority keys).

**Fixes:** `tokens.AgentRows` took an agent's provider from a map's first key, so the U page and
`agentbus tokens` could name either provider of a two-provider agent, and a test failed about one run
in seven (#322). It now takes the provider with the most tokens today; on a tie, the agent's own provider when it is
among them, else the first by name.

**Docs and the site:**

- **Five-minute quick start** (#328, `docs/quickstart.md`): install, `agentbus start`, a first task,
  an answered question, and how to stop, with the real output of each step. Linked from both READMEs.
- **Where it runs** (#329): both READMEs and the site say v0.x and one operator, and give a platform
  matrix (Linux, macOS, Windows) and a client matrix (Claude Code, Codex, Grok, Kimi Code).
- **CLAUDE.md split** (#330): a short agent contract with the rules that bite every agent; the
  architecture moved unchanged to `docs/architecture.md`, the operator notes to
  `docs/operator-notes.md`.
- **Community files** (#318): `CONTRIBUTING.md`, `SECURITY.md` (reports through GitHub's private
  vulnerability reporting), `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1), issue forms and a pull
  request template.
- The operational guides proofread, EN and FR (#316). The spec for the Plan and Requests views
  (#327; not built, see below).
- A presentation site in `site/` (EN, FR; #309, #312), its busmon screens aligned on one bundled
  monospace face (#315), accessibility and print fixes (#319). Plain HTML and CSS, no external
  request.

**Tests:** coverage raised for plan, quota and history (#313) and for tokens, models and usage
(#317); twelve Go native fuzz targets for the pure parsers (#320). Test files only.

## Not in this release

- **The Plan and Requests views redesign** is a spec only (#327). Its implementation waits for the
  person's go.
- **Plan-task priority** is phase 2 of the priority spec; only tracked requests have a priority.
- **GitLab and Bitbucket** have no API reader for the merge queue yet; they use the git fallback.
- **One dispatcher per host** is decided, not built (`docs/memory/decisions/2026-10-26-host-dispatcher.md`).
- **Windows** is not supported (it does not compile), and **macOS** still has no verified agent
  identity, so the dispatcher never wakes an agent there. See the README's "Where it runs".
- The site is not hosted anywhere by this release.

## Upgrade

```sh
./setup.sh update
```

What takes effect when:

- **Restart each project's services** for the merge queue, the `review-queue` and `merge-queue`
  checks and the answered-wait rule: `agentbus --project <p> service restart dispatch`.
- **Relaunch the agents** for the new deny of `agentbus request priority`, the skills' `request next`
  and reviewer-codex's role: per idle agent, `agentbus --project <p> reload <role> --as <your-name>`,
  or exit it, then `agentbus up <p> --resume`.
- **Reopen busmon** for the merge queue rows, one row per report, the read receipt, `+` / `-` on
  requests, `r` and the About and settings trims.
- **For the merge queue on GitHub**, have `gh` on PATH and logged in; without it the git fallback is
  used.
