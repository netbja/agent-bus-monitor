# v0.14.3 — an agent at work is seen at work

## Fixed

- **deploy worked six minutes while busmon showed it `idle`.** It drained its message and wrote
  the opening plan without declaring `working`; busmon shows only declared states, by design.
  The `agent-bus` skill now says so in the wake steps: declare `working` before starting.

## New

- **Observed activity, as a safety net.** The dispatch service inspects every pane whose
  identity it can verify, every 15 seconds, and publishes what it sees to `{p}:observed`
  (herdr's status, or the client's busy signature). It only reads: nothing is typed, no state is
  changed, and a pane that holds another process is not observed. The key expires two minutes
  after the last write, so a stopped service leaves nothing behind. A paused project is not
  observed; one pass takes at most five seconds, so observing never delays a wake. The key does
  not make a project exist: a deleted project is not revived by a late observation.
- busmon adds the flag **`busy`** to an agent whose pane runs a turn while it does not declare
  `working`. Its declared state stays as it was. The agent detail shows a new `Observed` row.
- `agentbus dispatch` in the foreground observes too; the default library config does not.

## Upgrade

`./setup.sh update`, then restart the services (`agentbus --project <p> service restart`) so
the dispatcher observes. The skills are links to the checkout, so the new wake step reaches an
agent the next time it loads `agent-bus`.
