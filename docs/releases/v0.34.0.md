# v0.34.0 — the broker's users can be switched on, one approval for a small change, a triage walk, conflicts go back to their owner, and a limit on work in flight

This release gathers the PRs merged into `dev` since v0.33.0, #722 to #775: 51 merged PRs, of which #762,
#766 and #774 are these notes, so 48 besides them. `dev` stood at `04c1755f` when they were last updated;
the first version was written against `65ae7509`. Every PR from #722 to #775 that merged is in it; the
ones that did not merge (#740, #745, #761) are not. `main` takes them as one promotion, on the person's
yes. These notes are their own PR.

**What changes for the person:** the broker's per-role users and the single approval are behind a
setting you turn on, and the automatic update's settings are read by nothing yet. **The
work-in-progress limit is the exception: it is on by default (2), so after upgrading `agentbus request
accept` enforces it at once; `board.wip_limit = 0` turns it off.** What you see without doing anything is
busmon (the Plan tab, For you, the Memory page, the project badge, `q` asking before it quits), `agentbus
--help`, the Board's alerts, and the roles' permission mode (below). **Auto-compact is also on by default**
(`dispatch.auto_compact`): the dispatcher types `/compact` into an agent's pane when its context stays
at 90 % for 10 minutes with no hand-off declared (below); `config.toml` turns it off.

**Broker ACL — you can now turn it on, and it stays off until you do** (#723, #732, #741; notes
`broker-acl-switch`, `broker-acl-rotate`, `broker-backup-snapshot`):

- **`./setup.sh acl on|off`** (#723) is the person's act, refused from an agent's environment or
  process tree before any password file is read. `on` writes a password file per user
  (`~/.config/agentbus/redis-<user>.env`, 0600), puts `users.acl` and the healthcheck's `ping.pass` in
  the broker's volume, recreates the broker, proves an `admin` login with the default user refused, then
  sets `broker.acl=on` and restarts the project services. A broker that does not take its users is put
  back, and the setting stays `off`. `off` removes both files, recreates the broker, proves
  `redis.env`'s password, then sets `broker.acl=off`; it needs no running broker. `on` is refused while the
  ACL is live: to remake the users, `acl off` then `acl on`. Both refuse while `REDIS_URL`,
  `REDIS_PASSWORD` or `AGENT_BUS_BROKER_ACL` is exported.
- **Rotation, status, purge** (#732). With `broker.acl` on, `./setup.sh rotate-redis-password` rotates
  each ACL user in turn (new file first, the previous kept as `.prev`, then `ACL SETUSER … resetpass`,
  a fresh login, `ACL SAVE`; `admin` last), with no recreate, then restarts the project services. A
  user the broker refuses stops it: the ones before stay rotated and saved. `./setup.sh status` shows
  `broker.acl` beside whether the volume holds `users.acl` and warns when they disagree.
  `./setup.sh uninstall --purge` sets `broker.acl` back to `off` once the volume is gone.
- **Backups hold the broker's snapshot** (#741). After the logical dump, `agentbus backup` runs
  `BGSAVE` and keeps the RDB as `broker.rdb`, which holds the keys with a TTL that the logical dump
  skips. It is copied only if it carries a marker written to the connected broker just before, so
  another broker's file is never taken for this one. When any step fails, the archive is logical only and
  the manifest's `left_out` says why. **Restoring `broker.rdb` is manual**; the steps are in the
  operator note. With `broker.acl` on, only `admin` takes it: the scheduled backup runs as the
  `dispatcher` user and stays logical only.
- **Still true:** `broker.acl` defaults to `off`; with it off, ACL refusals in the CLI are a courtesy
  message, not a barrier; and agents run as your OS user, so ACL users protect against mistakes, not a
  hostile agent.

**Approvals and `deliver`** (#726, #731, #737; spec `2026-11-21-single-approval-design`):

- **`agentbus deliver --dry-run` prints the change's size class** (#731): `size: small: N lines, M files`,
  `small (docs only)`, or `not small (<reason>)`. It is read from `git diff --numstat` against the
  merge-base. Small means within `small_max_lines` (150) and `small_max_files` (5), with no binary
  file and no never-small path (`bus/**`, setup, broker and ACL files, secrets, CI, `skills/**`, the
  gate's own files, `mergequeue/**`, `config/**`).
- **One approval for a small change, per project** (#737, #726). In `config.toml`'s
  `[project.<name>.delivery]`: `single_approval` (`off` or `small`), `small_max_lines`, `small_max_files`
  and `same_provider_ok` (`off`, `docs`, `small`). These four are the person's: `agentbus config set`
  refuses them. `never_small` (globs added to the defaults) only narrows the gate, so agents may set it.
  With `single_approval = "small"`, `deliver` accepts one current approval on the head when no reviewer's
  latest verdict is a reject, the change is small, and the approver is of another provider than the
  author (or of the same one and the change is in `same_provider_ok`'s class). The PR body says
  `single approval (small: …; approved by <r>)`. Refusals name the rule that failed. With two approvals,
  or the person's yes (`--single-approval "<the person's yes, ask <id>>"`), nothing changes. **The
  default is `off`.**

**Triage and For you** (#730, #743, #753, #755; notes `report-needs`, `triage-by-target`,
`triage-dedupe-context`, `triage-dedupe-summary`):

- **`agentbus report --needs answer|read`** (#730) says a report needs the person. The `subscribe` JSON
  carries `"needs"` (additive in v1) and `agentbus history` prints `report (needs answer)`. Any other
  value is refused before anything is written.
- **For you holds one item per target** (#743). A merge is keyed by its PR, so a rebase keeps it. A
  line naming exactly one live target (`#<n>`, a branch, an ask's id) attaches to that item, and a
  waiting agent's newest report folds into its wait row. A report is an item only with `--needs`; a
  plain report is Activity only. The header's unread badge counts Activity's unread marks.
- **An item's page ends with its Context** (#753): the messages attached to it, newest first, at most
  3, the rest counted ("n older in Activity"). `1`-`3` or a click opens one in full.
- **`T` opens a summary of the actions** (#755): what the walk did (answered, sent, read), one line per
  item, then the next plan task. Enter opens an item's page above it and the walk goes on from there;
  Esc returns to the summary, and Esc on the summary ends triage.

**Conflicts go back to their owner** (#728, #733, #752; notes `conflict-owner`, `conflict-owner-handoff`):

- **Detection** (#733). Each merge-queue pass judges the approved heads and the PRs the forge flags
  with `git merge-tree --write-tree` against the base tip, in an empty bare repository with an isolated
  `HOME`: no hook, merge driver or attribute of the repository runs. git older than 2.42 judges nothing.
  A confirmed conflict leaves the items for `Conflicting`; what git could not judge is named in
  `conflict_check`, also shown by `agentbus merge-queue`.
- **Hand-off** (#752). A confirmed conflict goes to its owner (the board's claim or request branch,
  else a `<role>/` branch prefix that is a registered agent, else master), once per PR and head, with
  master's copy and no wake. Past `conflict.max_handoffs` (3; 0 sends the first to master) or
  `conflict.escalate_after` (2h; 0 no time bound), master gets the escalation, woken. The count goes
  when an approved head is clean or the PR is closed or merged. An owner who is `blocked` or `waiting`
  is sent nothing and not counted.

**Work in flight is limited** (#734, #735, #736, #747, #750; note `wip-limit`; spec `wip-limit-design`):

- **`board.wip_limit`** (#747): how many requests an agent may hold `accepted` when it starts another.
  Default 2, `0` no limit, per project, no env variable. **The person's alone**, from busmon's Shift+C
  or `config.toml`: `agentbus config set` refuses it.
- **Enforced by `agentbus request accept`** (#736, #750): a first accept at the limit is refused and names
  what the agent holds. A resume and a first accept of a request the person marked `high` are never refused; once
  accepted they count as held like any `accepted` request (two of them fill a limit of 2). A request in
  `review` or `blocked` is not `accepted`, so it does not count. **`agentbus request review <task> [--branch <b>] [<note>]`** (new) marks a step in
  review. `request send` to an agent at its limit is queued, with one line on stderr naming what it
  holds and who is under the limit. The three agent skills say when to mark review and how master routes
  at the limit.

**The Board says what it measures** (#756, #757, #758, #763; notes `board-drift-alerts`,
`board-drift-stranded-pop`, `board-drift-close-on-merge`; spec `board-drift-design`):

- **Alerts name their starting point** (#757): "no acceptance 40m since request", "no reply 3h since
  accept", "body lost (request 27h)". "No reply" fires only on an `accepted` request. The AGE column is now
  CHANGED (the last transition), and a task's detail lists Requested, Accepted, Responded and In review.
- **A closed pop that owns open requests tells master** (#758), once per episode and woken, with the
  line that brings it back (`agentbus pop <role> --resume <session>`, else plain `pop <role>`). The
  dispatcher still never relaunches a pop.
- **A review request closes when its branch merges** (#763, step 2). `agentbus request review <task>
  --branch <b> [--commit <sha>] [--more]`, run in the branch's checkout, records the head and the base
  tip it read, and refuses a head already in the base ("nothing to review"). Each merge-queue pass then
  closes the review requests whose reviewed head was delivered: `done`, `closed_on_merge {head, base}`,
  no reply, nobody woken; busmon's request detail says "closed on merge <head> into <base>". With
  `--more` the request goes back to `accepted` instead, and the last step (no `--more`) closes it. An
  `accepted` request is never closed on merge, and a failed fetch records no base, so that request is
  never closed this way. The agent skills say to pass `--more` on a step that is not the last.
- The spec's other steps (`report --task`/`--done`, the sentinel's board drift) are **not built**.

**busmon** (#724, #725, #727, #739, #742, #746, #749, #760; notes `plan-tab-layout`, `busmon-cli-flags-2`,
`person-name`, `busmon-three-fixes`, `busmon-memory-page`, `busmon-memory-edit`, `busmon-project-badge`):

- **Plan tab** (#724). It takes the lower zone's full height, and what arrives in Activity is counted on
  its tab (`1 Activity · 3 new`). From 130 columns a Releases column shows next, the loaded plan and the
  release tags (`V` toggles it below 130); Enter opens a release's plan read only.
- **Flags** (#725). `-l`'s MASTER is the registered `master` agent's declared state, `-` without one.
  `--url` (`-u`) sets `REDIS_URL` before any connection and a switched busmon keeps it; `--host` beside a
  URL exits 2. The picker is `--new` (`-k`).
- **`person.name`** (#727; env `AGENT_BUS_PERSON_NAME`, default empty): your name on the bus, used
  after `--as` and `identity.as` and before `pilot`. The settings page calls it "Your name".
- **Three fixes** (#739): `/resume` on a project neither paused nor suspended says there is nothing to
  resume; `G` with auto-scroll off names `display.follow`; the Requests view is titled "Requests" with
  the tab it came from as the way back.
- **`q` asks before busmon quits** (#760; setting `display.confirm_quit`, default on). A popup "Quit
  busmon?": `y` quits, `n`, Enter or Esc stay, any other key leaves it open. Ctrl-C and a typed `/quit`
  still quit at once. Shift+C "Ask before q quits" turns it off, and `q` then quits at once.
- **The project's name is a pill for the first 3 seconds** (#746); when busmon chose the project itself
  it says so once: `last project opened: <p> (no -p) · M to switch`.
- **Memory page, F7** (#742, #749). It lists the person's facts kept on this host, a topic per row, Enter
  for its observations. `a` adds one, `x` forgets one after `y`, `e` edits the topic's file in
  `$VISUAL`/`$EDITOR`; after an edit the whole memory is checked and the file is committed only when
  clean. All three are refused in an agent's environment and on a machine that is not the memory's host.

**Person memory, step 3** (#729; note `person-memory-cli`): `agentbus mem person` has `remember`,
`recall [--json]`, `show`, `list`, `check`, `forget` and `purge [--yes]`. `forget` and `purge` are
the person's and refuse an agent. `purge` names the commits that go and wants a typed `yes`.

**`agentbus update` prunes old release trees** (#748; note `quiet-update-prune`). After a successful
update, each `…/agentbus/src/vX.Y.Z` that its clone lists as a worktree is removed with
`git worktree remove` (never `--force`), unless it is the installed version, a kept snapshot or a holder
build still names it, or it has changes. An unreadable fact keeps every tree. `agentbus update --list`
shows each tree and why it is kept.

**Background work** (#738; note `background-ignore-helpers`): **`dispatch.background_ignore`** names
processes the background judgement never counts, whatever their CPU: by default `codebase-memory` and
`codex-code-mode` (`config.toml` only). A shell whose every child is such a helper is ignored too.
It is read at each look, with no restart. Generic names (`MainThread`, `import`, every `node` or `bash`)
are not in the default on purpose, because they would hide real work.

**`agentbus --help`** (#754) has gh's layout: nine groups, one `name: brief` line per command, then
FLAGS, EXAMPLES and LEARN MORE, nothing over 80 columns. `agentbus help <command>` keeps the detail. A
new command needs a `Brief` and one entry in `helpSections`, or the suite fails.

**Roles start in auto mode** (#764; note `roles-auto-mode`; the person, 2026-11-24). coder, coder2,
foureyes, architect (and `claude-fable`), sentinel, deploy and docs move from `bypassPermissions` or
`acceptEdits` to Claude Code's `auto`; security and infra stay `manual`, and master was already `auto`.
Ask rules still prompt and deny rules still block, and Claude Code's classifier decides the rest. After 3
blocks in a row (20 in a session) it asks in the pane, which the prompt notification rings: **a worker
can now stop on a prompt where bypass never stopped.** reviewer-codex runs on `gpt-6-luna`, read-only,
with `reviewer = "auto_review"` (Codex's automatic review answers its escalations instead of the person;
announced as elevated at launch), and every Codex agent's status line shows the tokens used. Workspace
trust is still not pre-accepted.

**Auto-compact: `/compact` when no hand-off comes** (#769, #775; note `auto-compact`; the person's answer A).
An agent whose context fill stays at `dispatch.context_urgent` (90 %) for 10 minutes with no hand-off
declared gets the fixed line `/compact` typed into its pane by the dispatcher, once per context episode,
Claude Code only. It uses the auto-clear's pane guards: a verified process, ready and idle, not focused,
not blocked, no wake being typed, no swap, its provider not held. master gets one notice, without a wake;
if master is being swapped it is delivered on a later pass, and no other `/compact` is typed while it is
owed. A `/compact` left unsent in the input tells the person and is not typed again in that episode. A
declared hand-off stays the auto-clear's. **`dispatch.auto_compact` is on by default** and is the
person's (busmon's Shift+C or `config.toml`; no env variable). It is read again each minute, which #775
declares as `live` after #769 merged without its entry in `config/applies.go` and turned `dev` red.
The holder's submit frame takes a new kind, `compact`: an older holder refuses it and types nothing, so
restart the holder with the dispatcher.

**Settings say when a change applies** (#765; note `settings-read-when`). Each setting is one of `live`
(busmon applies it at once, or a service re-reads it at its next pass or check), `at the next run`,
`on busmon restart`, `on service restart` (read once when dispatch, missions or the holder starts) or
`on agent restart`; the slowest reader decides. It is shown last in `agentbus config` (an `applies`
column, also in `--json`), in busmon's Shift+C detail, and in its save message, which no longer says
"next start of busmon" for a key busmon does not apply itself. A new setting needs its entry in
`config/applies.go` or the suite fails.

**Upgrading:** run `./setup.sh update`. `agentbus update` still refuses a `dev` build, so it is for the
release after this one. Restart the project's dispatch service when setup offers (and the holder with it, for auto-compact), which applies the
conflict hand-off, the background list and closing a review request on merge. Nothing here asks you to recreate the broker or to set
`broker.acl`; turn the ACL on with `./setup.sh acl on` only when you want it.

**Limits:**

- **The automatic update is not built.** `updates.auto` (`notify`), `updates.window` (`03:00-05:00`) and
  `updates.max_wait` (7 days) exist and busmon shows them, **but nothing reads them yet** (#751);
  only `updates.window` can be edited from busmon, the other two are `config.toml`'s.
- `broker.acl=on` was built and tested in this release's PRs; this note's author did not run it on a live
  broker. Restoring `broker.rdb` is manual and its steps were not replayed here.
- The conflict hand-off needs the dispatcher restarted to take effect.
- Auto-compact was tested in its PRs, not run by this note's author on a live pane.
- The roles' auto mode was not run against a live team by this note's author; its effect on prompts is
  as the PR describes it, and when a running agent takes its new mode was not checked.
