# v0.7.0 — configurable agent clients and repository security review

Roles can now run through **Claude Code, Codex or Kimi CLI**, using a common
project profile or a different profile per role. The client/provider's normal
**effort setting is preserved by default**; users can explicitly configure an
optional override where the adapter supports it.

## What changes

- Schema v2 adds named execution profiles with client, provider, model and native
  permission options. Profiles are selected as a whole, so changing client does
  not accidentally inherit another client's permissions or fallback model.
- The historical unversioned Claude manifest remains supported. Bootstrap and
  on-demand spawn use the same resolver and retain the selected manifest path.
- Additional clients can use a trusted local executable adapter with a JSON launch
  specification. Environment references keep credential values out of manifests.
- Skills install into the selected clients' discovery roots after source/collision
  checks. Launch instructions provide direct skill paths for schema v2.
- New on-demand `security` role and `agent-bus-security` skill review repository
  vulnerabilities and propose corrections. Foureyes retains correctness,
  regression and maintainability review. Existing findings are referenced rather
  than duplicated; security neither applies fixes nor creates a merge veto.
- Shared instructions and the daily-review wake message no longer assume a Claude
  reset command or one budget shared by every provider in a mixed team.
- Spawn preserves the caller's project directory. Workspace templates quote paths
  and retain the manifest selection, including paths with spaces or Unicode.

## Use it

Follow the [profile guide](../AGENT-PROFILES.md) and customize the
[mixed-team example](../../examples/roles.mixed.toml) for your accounts. Model
placeholders must be replaced. Set `ROLES_TOML` to the project's manifest path;
use `AGENT_LAUNCH_DRYRUN=1` to inspect the resolved launch without a model call.
Existing templates must be regenerated to adopt a different manifest path.
The Python tooling requires Python 3.11+.

This release changes launcher tooling, role instructions and documentation. It
does not change Go runtime sources or the bus protocol (still v1). No live broker,
agent session or installed binary is updated by publishing the release.

## Validation

- `bash tests/run.sh`: shell assertions and profile regressions pass.
- Python discovery: 26 tests pass (13 profile/launcher + 13 memory regressions).
- Memory/link checker, skill validator and `git diff --check`: pass.
- `go test -race -count=1 ./...`: all five packages pass against disposable
  Redis 8.6.3 at `127.0.0.1:32768`, explicitly selected through
  `AGENTBUS_TEST_REDIS_URL`; ambient `REDIS_URL` pointed to an invalid production
  placeholder. The operational broker was not used.
- `go build ./...` and `go vet ./...`: pass.

## Limits

- Adapter tests use simulated clients; no authenticated model inference or live
  bus interaction was performed. Local help/version checks covered Claude Code
  2.1.283, Codex 0.157.1 and Kimi CLI 0.41.0.
- Kimi's adapter targets the Markdown `--agent-file` interface, preserving the
  base prompt. It has no verified effort override; leave reasoning absent.
- Explicit effort support for a model/provider is declared by the operator with
  `reasoning_levels`, not discovered remotely. Native permissions are not portable
  equivalents; no automatic cross-provider fallback is introduced.
- For Claude/Kimi, the provider label describes native routing configured outside
  this manifest. For Codex, it selects an existing native provider configuration.
- Usage collectors still cover Claude sources only. Other usage is unavailable,
  not zero; retained snapshots remain historical observations. A child launch
  clears the inherited Claude session ID to avoid using its parent's transcript.
- No binary assets are attached: the changed tools and skills ship in the source
  archive, consistent with the previous release.
