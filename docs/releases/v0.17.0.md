# v0.17.0 — master pops agents without the classifier, and asks before deploy

Spec: `specs/2026-10-17-role-tool-rules-design.md` (rev 5: Bernard kept the
per-role rules and dropped the bus approval of rev 4).

## Why

On 2026-10-17 project-a's master, in auto mode, was denied `agent-spawn deploy` by Claude
Code's classifier ("Production Deploy"). Nothing in the launch said what a role may run, and a
denial never reaches the person.

## New

- **Role keys in `roles.toml`.** `pops = true` (master): its Claude Code session starts with
  `Bash(agent-spawn <role> *)` as an allow rule for every other role, through one `--settings`
  flag, so popping architect, coder or docs skips the prompt and the classifier.
- **`approval = "person"`** (deploy) turns that role's rule into an ask: Claude Code asks in
  master's pane before it runs `agent-spawn deploy`, in every permission mode but
  `bypassPermissions`.
- **`[roles.<r>.tool_rules]`** (`allow`, `ask`, `deny`) adds rules of a role's own. A rule that
  would allow every shell command, or names `agent-spawn` (those are derived), is refused; an ask
  on a `bypassPermissions` role too. Other clients get a note and no rules.

## What it does not do

The ask rule matches the command's text. Checked live on Claude Code 2.1.302 in auto mode:
`agent-spawn deploy` prompted, but `agent-spawn "deploy"` matched no rule, went to the classifier,
and ran. It is a convenience for the usual command, not a lock.
