# v0.17.0 — master pops agents without the classifier, a person approves the risky ones

Spec: `docs/superpowers/specs/2026-10-17-role-tool-rules-design.md` (rev 4, reviewed by Claude Code,
approved by Bernard).

## Why

On 2026-10-17 ai-tradex-solana's master, in auto mode, was denied `agent-spawn deploy` by Claude
Code's classifier ("Production Deploy"). Nothing in the launch said what a role may run, and a
denial never reaches the person.

## New

- **Role keys in `roles.toml`.** `pops = true` (master): its session gets
  `Bash(agent-spawn <role> *)` as an allow rule for every ordinary role, and as an ask rule for a
  role marked `approval = "person"`, through one `--settings` flag. `tool_rules = { allow, ask,
  deny }` adds rules of its own; a rule that would allow every shell command, or names
  `agent-spawn`, is refused.
- **A person's approval on the bus.** `agentbus approval ask <role> <reason>` puts the question
  in busmon (bell, panel) even while the agent has another question open; `agent-spawn` spends the
  answer through `agentbus approval use` (one approval, one pop, 30 minutes,
  `AGENT_BUS_APPROVAL_TTL`). `agentbus swap` spends it before it closes a pane and hands it to
  `agent-spawn`.
- **Agents do not answer asks.** `agentbus answer` exits 2 when `AGENT_BUS_AGENT` is set.

## What it does not do

It is a procedure gate. Redis cannot tell busmon from an agent: an agent that unsets
`AGENT_BUS_AGENT` can answer or pop ungated. Bernard's manual paths are busmon, or `agent-spawn`
from his own shell; in master's tab, `! agent-spawn deploy` is gated like master itself.

## Checked live

Claude Code 2.1.302: in auto mode `agent-spawn architect` ran unprompted, `agent-spawn deploy`
prompted, and `agent-spawn "deploy"` went to the classifier, which let it run. The ask rule is a
convenience; the bus approval is what holds.
