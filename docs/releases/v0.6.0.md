# v0.6.0 — coordination recovery and shared agent memory

Released at `0484c5d`. The previous tag was v0.5.1; remote tags and GitHub
releases were independently checked on 2026-09-19 and stopped at v0.5.1, with
v0.6.0 unused.

## Included — merged through 0484c5d

- Recover pending Redis Streams deliveries across one-shot subscriber restarts,
  acknowledge only after complete output, and mark possible duplicate delivery.
- Track explicit acceptance, blockage and completion on the existing board.
  Technical delivery never implies acceptance or agent execution.
- Preserve bounded full Unicode text and expose completeness/retention limits.
- Make busmon message details and request follow-up readable, preserve snapshots
  during broker outages, and avoid interpreting silence as an agent's death.
- Document request verbs, cursor semantics and agent duties.

## Also included — merged after this file was first drafted

- Peers disconnect when idle; only master brings them back, through the herdr
  pane rather than the bus, because a command addressed to an unarmed agent is
  retained but never delivered. Cursor semantics stated precisely: pending
  entries remain recoverable below `last-delivered-id`, while entries already
  acknowledged — or skipped when the group was created — are not recovered by
  lowering `--since` (PR #38).
- Shared memory shipped as one piece: the `docs/memory/` reference, `AGENTS.md`
  as the entry point for every agent whatever the model, the boot path through
  six role briefings, three skills and CLAUDE.md, and `scripts/check-memory.py`
  with 13 regression tests (PR #39).

## Compatibility and rollout

Subscribe protocol remains v1; additions are additive. Installations may contain
multiple agentbus/busmon copies. Check actual executable paths and running
processes on each host. Old/new subscribers must not overlap for the same
project-agent pair. Binary replacement does not itself decide how to handle
existing pending or unread work: preserve groups and choose recovery cursors
explicitly. No automatic backlog abandonment, replay or project reset.

Output written is not proof of receipt; no exactly-once agent-action promise.
The board retains metadata without automatic GC; stream bodies can expire or be
trimmed. Memory notes are context, never fresh authorization to deploy or merge.
