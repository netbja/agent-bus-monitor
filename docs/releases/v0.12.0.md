# v0.12.0 — project services: dispatch and missions outlive the workspace

Until now `dispatch` and the missions conductor ran as herdr tabs. Closing the workspace, or
herdr itself, stopped them, which could interrupt an integration halfway. Nothing restarted them
after a crash, and their logs were only visible while someone watched the tab.

## What changes

### dispatch and missions are user services

`agentbus up` starts both under the operating system's own service manager:
- systemd `--user` on Linux;
- launchd on macOS (a LaunchAgent).

No supervisor of ours is added.
- **They no longer depend on the workspace.** Closing busmon, the workspace or herdr does not
  stop them. The dispatcher waits while herdr is away (`dispatch waiting herdr`) and resumes
  when it returns.
- **Never at login.** A unit is never enabled, and a plist is kept outside
  `~/Library/LaunchAgents`, so a reboot starts no project. `agentbus up` does.
- **An explicit fallback.** Without a usable manager, `up` says why and opens dispatch and
  missions as herdr tabs, as before. `--tabs` forces that. No hidden background process.
- **A re-run never interrupts an integration.** A busy conductor is left running; a changed
  configuration applies at its next `service restart`.
- **Your flags still apply.** `--no-dispatch` and `--no-missions` skip a service. Paths with
  spaces work, and the herdr session is carried over.
- **Older templates.** A template that still holds dispatch and missions tabs works: in service
  mode `up` does not open those tabs.

### Bounded restarts, never a loop

A service exits 0 when it must not run again, and 1 when a restart can help. Both managers
restart only on 1.

| Situation | Restarted |
|---|---|
| Explicit stop (`agentbus down`, `service stop`, logout) | no |
| Project deleted (`busmon --delete`) | no; the service stops within 5 s and recreates nothing |
| Another instance holds the lease (a herdr tab, another machine) | not needed: the service stays in `standby`, checks the lease every 15 s, and takes over once it is free |
| Invalid configuration (environment file, `--repo`) | no |
| Transient failure (broker unreachable, …) | yes, every 5–10 s |
| 5 failures in 10 minutes | no (`gave up`); the next `agentbus up` tries again |

The dispatch lease and the conductor's lock and lease are unchanged.

### Watching and stopping

- **busmon's header** reads `dispatch ready`, `dispatch waiting herdr`, `missions idle`,
  `missions busy`, `missions failed`, `gave up`, `stopped`. A service whose process vanished
  without a word shows `down` after 20 s.
- **`F3` (or `s`) opens the Services overlay**: for each service its state, last activity,
  detail, last error, host and log, and the tail of the log when the service runs on this
  machine. busmon reads the state from Redis (`{p}:services`), so it works from another
  machine too.
- **The commands:**

  | Command | What it does |
  |---|---|
  | `agentbus down <p>` | stops the project's services and deletes nothing; it says when an integration was interrupted |
  | `agentbus --project <p> service status` | the manager's view and the last published state |
  | `agentbus --project <p> service logs [kind] [-n N]` | the service's own log, rotated at 1 MiB × 3 |
  | `agentbus --project <p> service start\|stop\|restart\|remove [kind]` | one service |
  | `agentbus service list` | every project's services on this machine |

- **An interrupted integration.** When a stop interrupts a check or an integration, its tests
  are killed with their process group. The conductor redoes that step at its next start, as it
  already did after a crash.

### Removal, uninstall and secrets

- `busmon --delete <p>` stops and removes the project's services on this machine before it
  deletes the keys. If the removal fails, nothing is deleted.
- `./setup.sh uninstall` removes every project's services first. `install` and `status` list
  them. A running service keeps the binary it started with, so `install` says which services
  to restart.
- The broker password and the herdr session are kept in
  `~/.config/agentbus/services/<p>.env`, mode 0600 in a 0700 directory. A group- or
  world-readable file is refused. No unit, plist, argument or log holds a secret.

## Upgrading

`./setup.sh update`, then `agentbus up <project>` for each project you use. The first `up`
installs the services and stops opening the dispatch and missions tabs. An old dispatch or
missions tab that is still open keeps its lease, and the service waits in `standby`. Close the
tab: the service takes over within about 30 s, once the lease lapses.

## Validation

All tests used a disposable Redis (`AGENTBUS_TEST_REDIS_URL=redis://127.0.0.1:6392`). The
operational broker was not used, and no real service manager was touched: every test uses fakes
of `systemctl`, `launchctl`, herdr and docker.

- `go build`, `go vet`, `go test ./... -race -count=1`, `bash tests/run.sh` and
  `agentbus mem check` pass.
- `service/`: unit and plist generation (quoting, no secret, never enabled at login), the env
  file (0600, refused when readable by others), log rotation, restart budget, detection with an
  explicit reason.
- `service run`: ready, waiting herdr and stopped states; failures counted until `gave up`; a
  deleted project stops the service, which recreates no key; a bad `--repo` is not restarted;
  `standby` while another instance holds the lease, then taking over once it is free.
- `agentbus up`: services started before the workspace; no service tab opened, even from an
  older template; `--no-dispatch`; restart only on a changed configuration; explicit tab
  fallback; `--tabs`; a temporary `go run` binary is refused for a unit.
- `agentbus down` and `service`: stop without deleting, the interrupted-integration message,
  start clears the budget, logs, remove keeps logs, `remove --all`.
- A generated unit with spaces in its paths passes `systemd-analyze --user verify` (read-only, nothing
  loaded), and the plist is well-formed XML (`xmllint`).
- busmon: state facts, header words, the Services overlay, and `--delete` removing the services
  first.
- `tests/installer_test.sh`: uninstall removes the services first; install lists the running
  ones.

## Limits

- macOS (launchd) is tested only against a fake `launchctl`, not natively.
- A service runs on the machine where `up` ran. From another machine busmon shows its state, but
  not its log.
- `busmon --delete` (SCAN then DEL) can race one state write into an orphan key. The `EXISTS`
  guard makes this unlikely, but the write is not fenced by a lease.
