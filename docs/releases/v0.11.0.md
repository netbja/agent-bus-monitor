# v0.11.0 — a first run that works; setup, update, uninstall; the docs agent

This release comes from a first install on a clean machine. Four things failed or were awkward:
- `bootstrap new` stopped on `skill not found … wayfinder`;
- `Ctrl+B` then `↑` did nothing, and herdr answered `plugin_action_not_found`;
- herdr-plus was not installed in a standard place;
- opening a project took several commands, then a key sequence.

## What changes

### `setup.sh`: install, update, uninstall, status

`install.sh` is now `setup.sh`. `./install.sh` remains as an alias of `./setup.sh install`.

- **`install`** builds `agentbus` and `busmon`, stamped with their release, into the repository
  and `~/.local/bin`. It installs herdr if asked (`--install-herdr`) and registers herdr-plus with
  herdr (`herdr plugin install cloudmanic/herdr-plus --ref v0.1.16`), or links a local checkout
  (`HERDR_PLUS_PATH`). It then checks that the Projects action exists. That check is the fix for
  `plugin_action_not_found`. It also adds the `Ctrl+B` `↑` binding, clones the external skills
  (`mattpocock/skills` at `v1.3.1`) into `~/.local/share/agentbus/skills/mattpocock`, and starts
  Redis. `--dry-run` shows what would change.
- **The binding now reaches a fresh machine and a running herdr.** Before, the binding was
  skipped when herdr had never run, because `config.toml` did not exist yet. Now setup creates
  the file with just the binding; herdr accepts a partial config. It then runs
  `herdr server reload-config`, so a herdr that is already open picks the binding up at once.
  `HERDR_CONFIG_PATH` is honoured.
- **`update`** refuses a dirty tree, runs `git pull --ff-only`, reinstalls, then prints
  `updated vA -> vB` with the release notes in between.
- **`uninstall`** asks at each step. `--yes` makes the cautious choices: our binaries, links,
  binding and skills go, herdr-plus stays, and Redis is stopped with its data kept. `--purge` also
  deletes the data. Without a terminal and without `--yes`, it refuses.
- **`status`** shows versions, `PATH` order, skills, herdr-plus, the binding and Redis.

### A missing skill no longer stops a team

When a role names a skill that is not installed, the agent starts without it, with a warning:
`warning: skill <name> not found (run ./setup.sh install); <role> starts without it`. External
skills are looked up in `POCOCK_SKILLS_ROOT`, then in setup's clone, then in the old
`~/Tools/herdr-plugins` location. `agentbus roles install-skills` stays strict.

### `agentbus up`: one command from nothing to an open team

`agentbus up <project> [<path>] [--as <your-name>]` provisions the project with bootstrap (all of
its options apply) and, inside herdr, opens the workspace directly. If the workspace is already
open, it focuses it instead. Outside herdr it provisions the project and says how to open it.
`Ctrl+B` then `↑` still reopens a project later.

### busmon first, as you

The bootstrap template now opens **busmon as the first, focused tab**. `bootstrap --as <name>`
(and `agentbus up --as`) puts that name on busmon, which shows `♙ <Name> [human]`.

### A discreet update notice

busmon checks GitHub's latest release once a day (cached in `~/.cache/agentbus/latest.json`,
3-second timeout, silent on failure). When a newer release exists, its header shows a muted
`↑ vX.Y.Z`. A development build never checks, and neither does `AGENT_BUS_NO_UPDATE_CHECK=1`.
`agentbus version` and `busmon --version` print the release.

### The docs agent

A new `docs` role (Sonnet, `acceptEdits`, on demand) uses the `agent-bus-docs` skill. It updates
the documentation of a finished change and opens a pull request from `pr/<change>`; it never
merges. A change opts in with `"docs": "<agent>"` in `missions.json`. When the change completes,
the conductor sends that agent one directive naming the branch, the head and the counts. The
directive is written atomically with the `complete` notice.

### Security read of the role launcher (Grok)

Grok's read found no Critical issue; every finding was inherited from the Python version.
Fixed:
- `env_refs` refuses loader and hook variables: `LD_*`, `DYLD_*`, `HERDR_*`, `BASH_ENV`, `ENV`,
  `NODE_OPTIONS`, `GIT_SSH(_COMMAND)`, `GIT_CONFIG*` (which can set any git option), `GIT_DIR`,
  editors and pagers, `PYTHON*`, `PERL5*`, `RUBY*` and others;
- `ANTHROPIC_API_KEY` is dropped for every client, unless `AGENT_LAUNCH_KEEP_API_KEY=1` or
  `env_refs` names it;
- elevated options (`bypassPermissions`, `danger-full-access`, `approval=never`, `--yolo`) are
  announced on stderr before the client starts;
- a skill link is named after the manifest's skill, never after its resolved directory;
- `bind` uses the pane from before `env_refs`.

Kept for later (minor): the skill-install check-then-rename window, a role file symlinked outside
`ROLES_DIR`, and the launch cache's residuals (a symlinked cache root, ownership and ACLs,
parent directories).

### Documentation

- The README no longer carries one section per release. It has a quick start and points to the
  new [`CHANGELOG.md`](../../CHANGELOG.md) and to these notes.
- The operational guides (EN/FR) describe `setup.sh` and `agentbus up`.

## Upgrading

From a v0.10 checkout: `git pull && ./setup.sh install`. From then on, use `./setup.sh update`.
A herdr-plus you installed by hand under `~/Tools` is linked as before. Otherwise setup registers
the tagged release.

## Validation

Disposable Redis via `AGENTBUS_TEST_REDIS_URL=redis://127.0.0.1:6392`; the operational broker was
not used. The installer test runs a fake `docker` and a fake `herdr`.

- `go build`, `go vet`, `go test ./... -race -count=1`, `bash tests/run.sh` and
  `agentbus mem check` pass.
- **A clean machine.** `setup.sh install` ran with a throwaway `HOME`, the real skills download
  from GitHub, and a fake `docker` and `herdr`. `wayfinder` and the other skills were cloned at
  `v1.3.1` and linked. `status` and `uninstall --yes` behaved as described above. This run found
  the missing binding on a machine where herdr had never run (fixed above).
- **`agentbus up` in a real herdr**, on a throwaway project whose manifest starts no agent:
  - the workspace opened with busmon first, showing `♙ Bernard [human]` and `dispatch up`;
  - a second `up` focused it instead of opening another;
  - outside herdr, it provisioned the project and explained how to open it.
- **A mission change from start to end.** A throwaway repository went through every step: a
  mission, the scope and test checks, the 4-eyes review, the integration into `change/greet`,
  then `complete`. The `docs` directive was sent once, with `complete`. Grok then acted as the
  docs agent. It branched `pr/greet` from that head and changed only the README, accurately. It
  pushed the branch, left `main` untouched, asked `foureyes` for the review, and put the PR body
  in its report (the remote was not GitHub).
- **Codex's final review**: no Critical finding; eight Important and one Minor, all fixed with a
  test that failed first.
  - `uninstall --dry-run` is refused; uninstall had no dry run, and removed things anyway.
  - The binding is removed only when the block is exactly the one setup wrote. An edited block
    is reported and kept, so the next section of the config can no longer be lost.
  - Only a skills clone that setup made is updated or removed, and only when it has no local
    changes.
  - A complete signal retried by Redis is not sent twice. The script checks its own record
    before it appends anything.
  - `env_refs` may not set `GIT_CONFIG*` (which can set any git option), `GIT_DIR`, editors or
    pagers.
  - A workspace that `agentbus up` could not finish is closed, so a retry opens it fresh.
  - A new herdr-plus pin reaches a herdr-plus that setup installed.
  - A missing skill no longer stops bootstrap (`roles install --missing-ok`).
  - A `SKILLS_DEST` with a space works.
