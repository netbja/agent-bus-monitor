# v0.26.0 — one settings file, a team that notices it has stalled, history, backups and notifications

This release gathers everything merged since v0.24.0 (PRs #192 to #284). v0.25 was planned
(`docs/plans/v0.25.json`) but never tagged: its work is here too, with the v0.26 batch
(`docs/plans/v0.26.json`).

**Public release groundwork** (#192-#198, #201, #202, #205):

- **MIT licence** (#192), and private references scrubbed from code, docs and examples (#195). The
  CLI's default sender, when `AGENT_BUS_AGENT` is unset, is now `anonymous`; entries already on a
  bus keep the sender they were written with.
- **A Redis password of its own** (#194). `./setup.sh install` on a fresh broker writes a random
  password to `~/.config/agentbus/redis.env` (0600); compose, `agentbus` and `busmon` read it, and
  it never appears on a command line. An install made before keeps the historical password, and
  health `redis-password` warns about it until you run `./setup.sh rotate-redis-password` (asks
  first; `--dry-run` shows what it would do).
- **A machine with no agent CLI** (#193): setup warns with each client's install page, and `up`
  warns about the tabs whose CLI it cannot find, starts them anyway, and refuses only when none of
  the team's is found.
- **First-run fixes** (#198, #201, #202): `up` right after `docker compose up` waits for the
  broker to answer before marking the services (no more `LOADING`); `busmon` without a project
  points to `--list` and `--pick`; `up` explains a refused project name and suggests the valid one;
  `agentbus agents` on an empty project says so.
- `herdr plugin install` from herdr's list now stops with how to install from a clone, instead of
  registering a plugin with no binaries (#196). master answers people on the bus (#197).
- **Docs for the public release** (#205): a French README, a "First run" section, both operational
  guides.

**One settings file, `config.toml`** (#208-#211, #213, #247, #253, #254, spec
`docs/superpowers/specs/2026-10-29-config-file-design.md`):

- Every tunable has one entry in a registry: its key in `~/.config/agentbus/config.toml`, its
  environment variable, its default and its rules. The environment wins over the file, which wins
  over the legacy `busmon.toml`, which wins over the default.
- busmon, the person's name (`agentbus identity set`), the project services and the writers all
  read through it. A service reads the `config.toml` of the `XDG_CONFIG_HOME` its env file names.
- **`agentbus config [--project <p>] [--json]`** prints each value and where it comes from, never a
  password or a URL; `--project` adds what that project's services see.
- **A warning for every skipped environment value.** A variable set to a value its rule does not
  take is skipped (the next source applies) and said, naming the variable, never the value. This
  now covers every registry key, not only the file's own problems.
- **busmon's settings page, `C`** (#253): edit `config.toml` by group; theme, fade, bell and the
  reminder timings apply at once, the rest at busmon's next start. The file is edited line by line
  and read back before it replaces the old one.
- **Small behaviour changes:** a relative `XDG_CONFIG_HOME` is now ignored, as the XDG spec says
  (busmon used to accept one); a negative `display.limit` in a file replays all history, as the flag
  always did; `agentbus identity set` is no longer refused by a name in `busmon.toml` (the new one
  wins, and it says so); `[updates] check = false` turns busmon's update check off.
- `[llm.<name>]` tables describe a local model's endpoint (#247); `sentinel.reload` (`on`,
  `propose`, `off`) sets whether sentinel reloads agents after a client update (#254).

**busmon** (#199, #204, #214-#222, #224, #227, #238, #240, #244, #266, #270, #271, #276, #279):

- **One list pattern for its pages.** Health F5 grouped by place (for you, in hand, fine) with the
  command to copy; Requests one line per group, unanswered threads folded after 7 days; Tokens `U`
  by zone; the recap and For you in the same format, newest first, identical items merged.
- **For you says what to do.** A plan task waiting for you opens with its Action row; with nothing
  for you, it shows what is in progress and the next decision.
- **The notice line**: at the footer's right, a quiet line for what happened by itself while
  busmon runs (a pause, a resume, an automatic `/clear`, a reload, a swap, a health change). No
  bell, no count.
- **Usage cards on `U`**: per provider, each window with a thin bar, a pace mark and its reset; a
  sentence says whether the limit is reached before the reset at this pace. Cards are capped at 80
  cells (#283).
- **Icons**, off by default: `display.icons = nerd | agent-font` (#271).
- Compose: Shift selects, PageUp/PageDown; `^V` pastes an image from the clipboard as a file path
  (never uploaded). Agent page: `Y` copies the whole report, `i` quotes what the agent needs into
  a reply. `←`/`→` step the lower tabs; `w` writes to master.
- Fixes: the reminder drops an answered ask (#214); Backspace lag with a full Activity feed (#220);
  a report notice stays unread until opened and reads as its report (#266); an answer follows a
  replaced ask, and typed text is never lost (#270); tab pills padded (#227).

**The stall guard** (#228, #230, #231, #243, #252, spec
`docs/superpowers/specs/2026-11-01-stall-guard-design.md`): three health checks. `team-stall`
fails when every agent has been idle 15 minutes with ready work in the plan and nothing open, and
wakes sentinel, which sends master the next task; `clear-stall` warns on a hand-off nobody cleared;
`quiet-agent` warns when an agent went quiet on a directive. Each wakes the agent or master once,
and you are told once per stall. **Chain reliability** (#243): a declared hand-off is the idle,
and an escalation re-opens when new work arrives.

**Automatic agent state** (#234, #237, #241, #246, #255, #264, #265, spec
`docs/superpowers/specs/2026-11-01-auto-state-design.md`): Claude Code, Codex and Grok launches
carry turn hooks that flip the agent between idle and working, without a status entry. A
declaration still wins. busmon marks a flipped state `(turn)` and flags `idle?` on a working agent
whose pane has been ready for 10 minutes. Kimi has no hooks.

**History** (#229, #236, #239, spec `docs/superpowers/specs/2026-11-01-history-design.md`): the
dispatch service archives the streams to day files under the state directory (90 days, 256 MiB,
secrets redacted); `agentbus history` reads the archive and the live streams together and says
where a gap is; busmon's `H` page.

**Health** (#226, #245, #257): `github` (SSH and HTTPS reachable; warns after an hour with both
down, never fails), `disk` (the filesystems agent-bus depends on; warn under 10 % or 5 GiB, fail
under 2 % or 1 GiB; sentinel never deletes anything), `llm-endpoint` (the local model peer's
endpoint).

**`agentbus start`** (#248, #258, #260, #268, spec
`docs/superpowers/specs/2026-11-01-agentbus-start-design.md`): one command from a folder to a
running team, inside herdr or outside it. It deduces the project, your name and the team, asks
only what it cannot, and runs `up`.

**Forge delivery** (#249, #272, #277, #278): `agentbus deliver <branch>` delivers a reviewed branch
only when the 4-eyes approval names its exact commit (`verdict --head`). The forge comes from
`origin` (`delivery.forge`, default `auto`): GitHub and GitLab through `gh`/`glab`, Bitbucket the
page to open, a local mode that pushes nothing. A plan merge task waits for you only once delivered.

**Backups** (#250, #262, #269, #281, spec `docs/superpowers/specs/2026-11-01-backup-design.md`):
`agentbus backup` writes one `.tar.zst` archive of every project of the host (Redis per project,
templates, settings), verified before any restore; `agentbus restore` is all or nothing per project
and never runs over a live one. Secrets (`redis.env`, the services' env files, `notify.toml`) are
left out unless `--secrets`, which encrypts them with `age` to a recipient. `backup.schedule =
daily` makes the dispatch service take one a day; `backup.after_command` runs your own command
after each archive. Health `backup` reminds you.

**Notifications** (#282, #284, spec `docs/superpowers/specs/2026-11-03-notifications-design.md`):
off until you turn them on. Targets (ntfy, public `ntfy.sh` by default, a Discord webhook, the
desktop) and their secrets go in `~/.config/agentbus/notify.toml` (0600, never written by
agentbus, denied to every role); the settings are `notify.*` in `config.toml`. You are told what
waits for you (decisions, a team stall, a fail, a for-you warning, a notice only you can act on, a
pane on its prompt) after 2 minutes, in a summary by default; quiet hours, a per-hour limit and the
events are configurable. Full text goes only to a private target (the desktop or a self-hosted
ntfy). `agentbus notifications test` sends a test from your own shell; health `notifications`.

**Local LLM peer** (#207, #256, #257, #259, #273): `agentbus peer` runs a local OpenAI-compatible
model as a read-only test peer: it answers directives and challenges with file reads under the
project root, never a shell or a write. A security review hardened its file access.

**Roles and agents** (#233, #242, #246, #263, #267, #274, #275, #280):

- **Automatic `/clear` after a hand-off is on by default** (#263). See the upgrade steps to turn it
  off. `AGENT_BUS_AUTO_CLEAR` takes `0` and `1` only.
- **Pop roles retire themselves** (#274, #275, #280): once a pop has been idle with nothing open,
  master gets one directive to `agentbus retire <role> --forget`; a pop whose tab you closed by
  hand is unregistered too.
- **Compact output for agents** (#242): `subscribe --drain --brief`, `agents <name>...`,
  `health <check>...`, exact hand-off times.
- A quota window reported with a jittered reset sends one notice, not one per reading (#267).
  reviewer-codex may post its review without asking each time (#233).

**Known on this release:**

- **Health `backup` warns for a project never backed up**, by design, until its first archive:
  run `agentbus backup` once.
- **The `--secrets` path (`age`) was not exercised live on this host** (`age` is not installed
  here); its tests use a stand-in for `age`. Before relying on it, make one archive with
  `--secrets` and restore it with `agentbus restore --identity <file>` on a machine you can spare.
- `scripts/setup-legacy.sh` is still shipped.

## Upgrade

```sh
./setup.sh update
```

What takes effect when:

- **Restart each project's services** (`agentbus --project <p> service restart dispatch`, and
  `missions` where it runs) for the stall guard, history, the new health checks, the daily backup,
  notifications and `config.toml`.
- **Relaunch the agents** for the turn hooks: per idle agent,
  `agentbus --project <p> reload <role> --as <your-name>`, or exit it, then
  `agentbus up <p> --resume`. Codex asks once to trust its hooks; Grok runs its hook once you
  answer its folder-trust dialog.
- **Reopen busmon** for the pages, the settings page `C`, the notice line and the cards.
- **Automatic `/clear` is now on.** To turn it off everywhere, put `auto_clear = false` under
  `[dispatch]` in `~/.config/agentbus/config.toml`; for one project,
  `AGENT_BUS_AUTO_CLEAR=0 agentbus up <p>`. `up` rebuilds the services' env file from its shell, so
  a line added there by hand is lost at the next `up`.
- **An install from before #194 keeps the historical Redis password**: run
  `./setup.sh rotate-redis-password` when the warning shows.
- **Take a first backup** (`agentbus backup`) to clear health `backup`; `backup.schedule = daily`
  keeps it current.
- **Notifications stay off** until you write `notify.toml` and set `notify.on = true`.
