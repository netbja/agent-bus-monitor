# v0.24.0 — the installer in Go by default, busmon's pages read better, reloads checked first

This release gathers everything merged since v0.23.0 (PRs #167 to #190).

**Reload fixes** (#168, #170):

- **Every check before the kill.** `agentbus reload` now checks that the agent can be relaunched
  (inside herdr, the workspace open, one template tab) before it stops anything. A relaunch that
  could not run no longer leaves an agent stopped.
- **Pop roles come back through `agent-spawn`**, with the bind required, as `swap` does.
- **The agent's own open question blocks only `--fresh`.** A resumed conversation keeps the
  question, which stays in Redis.
- **The tab is read until it settles** after the exit (at most 20 s), since herdr's view lags it; a
  tab the relaunch skips is an error. `roles.toml` is found in the stamped checkout, as `up` finds
  its scripts.

**busmon** (#171-#179, #181, #190):

- **F3: the Redis card's page.** The Redis card is selectable; Enter opens a read-only page:
  memory, persistence, clients, each project's keys and stream lengths in an aligned table, the
  port bind and the container's last log lines. Facts it cannot read show `?`.
- **F3 stays live.** The Services and Redis pages read their facts fresh and again every 5 s while
  open. `←`/`→` move between the cards when they sit side by side.
- **Gauges in eighths.** In a true-colour terminal the account gauges fill in eighths of a cell on
  a track and slide to a new value in half a second; the figure changes at once. A window never
  observed reads `?` with no bar. 16 colours and no colour keep whole cells.
- **The header counts what is owed.** In orange, the Requests view's own count of what you owe
  (`2 requests waiting · oldest 3h`); muted, what agents owe each other (`4 between agents`). Each
  is absent at 0.
- **Pages read `Label:  value`**, the values of a block in one column, a long value wrapped under
  its value.
- **Start a plan task.** A plan task waiting for you has an `Action:` row under Owner: Enter or `s`
  opens the compose window to master, prefilled.
- **A cursor in the input line.** The one-line input and the filter line edit at a cursor: `←`
  `→` by character, Home/End or Ctrl+A/Ctrl+E to the ends, Delete, Ctrl+W back a word, Ctrl+U to the
  start. A draft and a completion put it at the end.

**Health `redis-version`** (#182): the broker is compared with the latest Redis release of its own
major, read once a day from GitHub (`~/.cache/agentbus/redis-latest.json`). Behind in its major is
a warning; a newer major is only named, since changing major is your decision. No successful check
for 48 hours reads `unknown`. You update the broker; sentinel never restarts or upgrades it.

**`{p}:usage` reads only the proved session** (#180): an agent's model and context come from the
session proved with its process, never from one an unverified status merely names.

**The installer in Go is the default** (#183, spec
`docs/superpowers/specs/2026-10-28-go-installer-design.md`):

- `./setup.sh` is now a thin script that builds `agentbus` and runs `agentbus setup`, with the same
  subcommands, flags, questions and output. It starts, stops or removes the `agent-bus-redis`
  container only when it belongs to this checkout.
- **The bash installer stays one release** as `scripts/setup-legacy.sh`, should the Go one fail on
  a machine. Report what made you use it: the next release removes it. `scripts/setup-go.sh` is
  kept one release as a shim to `./setup.sh`.
- `--force` has had no effect since v0.20: it now warns, and goes with the bash installer.

**Roles: `infra`, adopted** (#186, #187): a pop role for Ansible, Terraform/OpenTofu and IT
automation, on a manual profile with approval by the person. Only exact syntax and lint commands
run without a prompt; plans, checks, downloads and every change go through you, and secrets
(state, plan and variable files, vault passwords, cloud credentials) are denied. master pops it
only with your yes. The tool rules are defence in depth, not a lock.

**Specs, not built** (#184, #185): the feedback loop (`agentbus feedback`, read-only statistics
over the reviews the bus retains; a skill change proposed only after your yes) and one config file
(`config.toml`, and `agentbus config` to show each setting's value and where it comes from).

**Docs:** the README and the operational guides (EN, FR) cover this release (#189), including the
env file the services read. Plans: v0.24 (#169), v0.25 (#188). Tests: #173, #178.

## Upgrade

```sh
./setup.sh update
```

This update still runs the bash `setup.sh` of your checkout, which pulls, then runs the new
`./setup.sh`, now the Go installer.

What takes effect when:

- **Restart each project's dispatch service** (`agentbus --project <p> service restart dispatch`)
  for health `redis-version` and its daily release check.
- **Reopen busmon** for the new pages, gauges, header counts and the input cursor.
- **Relaunch master** for its pop rule for `infra` (asked of you). Per idle agent:
  `agentbus --project <p> reload <role> --as <your-name>`, or exit it, then
  `agentbus up <p> --resume`.
- **Automatic `/clear` stays off.** To turn it on, put the variable on the `up` line:
  `AGENT_BUS_AUTO_CLEAR=1 agentbus up <p>`. `up` builds the services' env file
  (`~/.config/agentbus/services/<p>.env`, `KEY="value"` lines) from its shell, keeping only the
  escalation target and the reload setting from the old file, so a line added there by hand is
  lost at the next `up`; an unquoted one stops the dispatcher on an invalid configuration.
- **If the Go installer fails**, run `scripts/setup-legacy.sh` with the same arguments, and say
  what happened.
