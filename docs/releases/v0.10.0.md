# v0.10.0 — missions, shared-memory tooling, installer

Large changes can now run across several agents and several days without the coordinator
holding the plan in its context. The plan lives in Git, a deterministic **conductor** runs it on
the bus, and master only decides what is blocked. Two smaller pieces ship alongside: `agentbus mem`
keeps the shared memory in `docs/memory/` checkable, and `./install.sh` sets up a machine in one
idempotent run. Nothing changes for agents that do not use missions.

## What changes

- **Missions** (`agentbus missions`, `agentbus mission …`). A change's tasks are described in
  `docs/changes/<change>/missions.json`: agent, reviewer, dependencies, allowed paths, test
  command and brief. The plan is read from Git at a given commit. The conductor is one process
  per project, a herdr tab with no LLM in it. It:
  - requests each mission once its dependencies are integrated;
  - rejects a delivery that touches files outside its allowed paths or whose tests fail;
  - opens a 4-eyes review on the assigned reviewer;
  - merges approved commits into `change/<change>` and runs the change's test suite there. It
    never touches `main` and never pushes.

  Every mission write is fenced by the `{p}:conductor` lease. The CLI only queues operations on
  `{p}:missionops`; the conductor alone applies them. Agents deliver with
  `agentbus request done <task> --commit <sha> --branch <b>`.
- **Operator commands.**
  - `mission load <path>@<commit>` loads a change, and `--force <reason>` loads a revised plan as
    rev n+1. A mission dropped from the plan is tombstoned, and a reintroduced one starts again.
  - `mission load --recover` rebuilds the state from the merge trailers on `change/<change>`
    after Redis is lost.
  - `mission retry`, `mission reassign <agent>` and `mission skip --reason` (marks a mission done
    so its dependents proceed; recorded in the verdict ledger).
  - `mission abort --reason`, `mission status [<change>]` and `mission show <change>/<id>`.
- **Timeouts.** A mission accepted but not delivered within its `timeout` (4h by default) is
  blocked and escalated to master. A delivery that arrives after the timeout is treated as late.
- **Crash safety.** The conductor repairs half-done integrations at startup. It refuses to
  merge in a dirty integration worktree and escalates that once. Effects that write to a stream
  are at least once.
- **busmon** shows `missions up/down` in the header. The bootstrap template opens a `missions`
  tab (`--no-missions` omits it).
- **`agentbus mem check | new | sync`** replaces the Python checker. It needs no project and no
  broker:
  - `check` validates the structure, links, metadata and reachability of `docs/memory/`, plus
    the copy of the index in AGENTS.md;
  - `new` writes a dated note stub;
  - `sync` refreshes the index copy.
  - `go test ./...` fails when the index copy drifts.
- **`./install.sh`.** It runs a preflight and checks Go against `go.mod`. It rebuilds `agentbus`
  and `busmon` on every run, into the repository (where bootstrap's tabs run them) and into
  `--bin-dir` (default `~/.local/bin`), and warns when another copy shadows them on `PATH`. It
  then links the role skills and starts Redis. herdr and herdr-plus are downloaded only with
  `--install-herdr`; herdr-plus is pinned to a tag. `--dry-run` changes nothing.

## Use it

```bash
./install.sh --dry-run && ./install.sh     # after every git pull
agentbus --project <p> missions            # or the bootstrap "missions" tab
agentbus --project <p> mission load docs/changes/<c>/missions.json@HEAD
agentbus --project <p> mission status
```

Projects bootstrapped before v0.10 need `scripts/bootstrap new <project>` again to get the
`missions` tab. Design: the [missions spec](../superpowers/specs/2026-10-11-missions-design.md) and
the plans for [slice 1](../superpowers/plans/2026-10-11-missions-slice1.md) and
[slice 2](../superpowers/plans/2026-10-11-missions-slice2.md).

## Validation

Disposable Redis via `AGENTBUS_TEST_REDIS_URL=redis://127.0.0.1:6392`; the operational broker was
not used.

- `go build ./...`, `go vet ./...` and `go test ./... -race -count=1` pass on `main` after both
  missions slices and the installer were merged. The mission tests run real `git` repositories,
  real merges and real test commands.
- `bash tests/run.sh` passes. The installer test covers a dry run that changes nothing, a real
  install into a copy of the repository that replaces a stale binary, an idempotent herdr config
  edit, a taken key left alone and an old Go refused.
- `agentbus mem check` passes on the repository.
- Reviews:
  - missions slice 1: two Codex checkpoints and a final Kimi review (approve);
  - missions slice 2: two Codex checkpoints and a final agy review (approve with fixes; every
    Important finding fixed);
  - installer: reviewed and corrected before merge.

## Limits

- The conductor and the agents share one machine and one repository. Running a mission's tests
  runs the agent's committed code as your user: load only plans you have reviewed, and keep
  secrets out of the conductor's environment.
- Deferred minors:
  - abort walks missions in map order;
  - attempt numbers are not capped at 99;
  - no test injects a failure in the middle of a Lua script.
- Python is still needed by `link-role-skills.sh` and the bootstrap template generator until
  they are ported.
