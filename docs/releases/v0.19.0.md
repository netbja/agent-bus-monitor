# v0.19.0 — project health core

Every installed project service now has a shared health view. The dispatcher runs bounded checks
in a separate goroutine under its lease, so slow inspection does not hold up command reconciliation.
Each result is written through a lease-fenced Lua script and timestamped with Redis `TIME`. Status
changes alone enter the capped transition log. Missing or stale readings display as `unknown`,
never as healthy.

The checks cover managed services and their restart budgets, verified agent identity and launch
evidence, model drift, visible progress, cmd consumer delivery and retained targets, quota freshness,
tracked secret-like paths, Redis exposure and credential-source confidence, service environment
permissions, installed versions and the read-only herdr probe. These checks do not read candidate
secret files or retain raw log, process-environment or pane contents. The runaway check is a warning
only and never stops an agent. Health remediation strings are static guidance, not commands the
dispatcher executes.

Use `agentbus --project <p> health list`, `detail <id>` and `log [<after-id>]` to inspect measured
state. Sentinel can add an independent annotation with `health note <id> <text>`; it cannot change
the measured result. A transition into `fail` sends one ordinary directive to the registered
sentinel, or the configured escalation target if sentinel is absent. Repeated observations in the
same failure episode do not create wake storms. A separate Redis-time mark sends one daily review
directive.

Sentinel may restart one failed dispatch or missions service once when its restart budget has room,
or refresh a failed local model catalogue. It waits for the next measurement after a repair and
escalates anything else. The old cron, budget-refresh, dispatcher-polling and peer-relay duties are
removed from its skill.

The dispatch service now refreshes per-agent usage at most every 15 minutes through a fenced writer.
It also refreshes the host-wide model catalogue once daily under a local lock. busmon adds a compact
health pill (`✓` when every check is current and `! N` otherwise), an F5 detail overlay with
remediation and sentinel notes, and retained health transitions in the `R` recap.

This release does not add a secret scanner, end-to-end canary, Redis key inventory, project-defined
checks, or Redis password generation/rotation. Health is diagnostic defense in depth, not a security
boundary.

Validation: `go build ./...`, `go vet ./...`,
`AGENTBUS_TEST_REDIS_URL=redis://127.0.0.1:6392 go test ./... -count=1`, and
`AGENTBUS_TEST_REDIS_URL=redis://127.0.0.1:6392 bash tests/run.sh`.
