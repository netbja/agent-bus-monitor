# v0.12.1 — dormant agents, cleanup from busmon, escalation target, how to start work

A small release, from moving two long-lived teams to v0.12: a replaced team must not stay on
screen as if it were working, old threads must not read as work waiting, and a team whose
coordinator is not `master` must still receive its escalations.

## New

- **Dormant agents are hidden, not relabelled.** Liveness is passive: an agent's last declared
  state stays until it declares another, so a replaced team kept showing `working` and
  `blocked`. busmon now leaves out of the Agents panel, and out of `@all`, an agent silent for over
  a day that is not listening, not the pilot and owed nothing. The panel counts them
  (`3 dormant (a shows)`) and `a` toggles them. Nothing is inferred about the agent itself.
- **`agentbus agents forget <agent>... [--force]`** retires agents for good: snapshot, usage, wake
  record, armed/gate/receiver keys and cmd group (the streams stay, they are history). It refuses
  an agent that is listening or declared a status in the last 10 minutes, unless `--force`.
- **`d` / `Delete` in busmon, then `y`.** On an agent: the same forget, with the same refusal. On an
  untracked request thread: a reply from you (`human=yes`, never wakes anyone) closes it, and its
  history stays. A tracked request is still closed by its owner. Any key other than `y` cancels.
- **The Requests count covers the last 24 hours.** Unanswered directives older than the
  dispatcher's horizon wake nobody; in a long-lived project there were 151 of them, most answered
  by a status or a report rather than a reply.
- **`today` on the Activity day separator**, in green, so today's lines stand out.
- **`agentbus up <p> --escalate-to <agent>`.** The dispatcher and the conductor escalated to an
  agent named `master`, so a team whose coordinator has another name (`claude-hl-master`, say) lost
  every escalation and `complete` notice. The target is recorded in the project's service
  environment (`AGENT_BUS_ESCALATE_TO`): a later `agentbus up <p>` keeps it, `--escalate-to master`
  sets it back. An invalid name is refused by `up`, and a service that finds one stops with
  `failed` instead of restarting. The missions service picks a new target at its next restart, as
  for any configuration change.

## Fixes

- An agent launched and bound but with no status yet showed a 1970 age (`497780h ago`); it is now
  undated (`never` in `agentbus agents`).
- `agentbus up` outside herdr named the project as the herdr session to start, even with `--session`.
- `roles.toml`: Opus 5.5 for coder, foureyes, architect and security; Sonnet 5.5 for master, deploy and
  docs; Haiku 5.5 for sentinel. The guides say that `--as` takes a lowercase name.
- **`setup.sh` no longer warns that herdr-plus's projects action is missing when herdr is simply
  not running.** The plugin list is read from disk, but the action list comes from the running
  herdr server. Run outside a herdr session, `herdr plugin action list` answers
  `server_not_running`, and `install`/`status` took that for a missing action. They now say the
  picker was not checked (`no herdr server running here`) and keep the warning for an action that
  is really absent. Nothing to repair on a machine that showed the warning.
- The master skill said to start the conductor in its own tab (`agentbus missions`). Since v0.12.0
  it is the project's `missions` service, started by `agentbus up`.

## Documentation

- **Operational guide, new section 6 (EN and FR): starting work.** Once the team is up, how to
  hand it a small task (ask `master` from busmon, with a definition of done) and a large,
  multi-day change: plan it as missions in Git, review the plan, `mission load` it at a commit,
  follow it, decide on escalations, resume across days and reboots, merge `change/<c>` yourself.
- **Scenario B2: moving a team from before v0.12.** Services only, from a terminal outside herdr
  (`--session`, `--escalate-to`), close the old wake tabs, have each agent declare itself once.

## Upgrade

`./setup.sh update`. Running services keep their binary until
`agentbus --project <p> service restart dispatch` (and `missions`, when it is idle).
