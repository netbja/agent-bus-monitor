# v0.31.0 — a failed CI check back to its author, braille sparklines, a readable light theme, and the dispatch service in its own package

This release gathers the 32 PRs merged into `dev` since v0.30.0, #611 to #644 (#637 and #639 were
closed: the CI loop's wiring merged as #641). `main` took them as one promotion, at `f018542c`.
These notes are their own PR. The person gets a CI loop, two busmon display changes and atomic file writes. Most of the
rest is internal: the dispatch service's runtime moved out of `cmd/agentbus` with no change in
behaviour. What the release leaves out is listed at the end.

**A failed CI check goes back to its author** (#622 idea, #631 and #633 spec
`docs/superpowers/specs/2026-11-19-ci-loop-design.md`, #636, #641):

- **The loop** (#636, #641): each merge-queue pass of the dispatch service reads the open PRs' checks
  with the same `gh pr list` call it already makes. A PR whose checks failed, with nothing still
  running, goes back to the author of its head (the agent named by the verdict ledger's entries on
  that head, else master or the service's `--escalate-to` agent), with the failing checks and their
  links (`gh run view --log-failed` for a GitHub Actions run). Master gets a copy without a wake. A draft is skipped.
- **At most `ci.max_handoffs` times** (default 3; `0` sends every red PR straight to the stop). A
  new head counts toward the same cap, and green does not reset it. At the cap the loop stops: master
  is told, and the person gets a For you notice naming `agentbus ci reset <pr>`.
- **`agentbus ci reset <pr>`** re-opens a stopped PR's loop. It is the person's only: it is
  refused in an agent's environment. busmon's `/` palette has it too, as `/ci reset <pr>`, run after
  `y`.
- **A red base is not the author's failure** (#633): before a hand-off, one `gh api graphql` call
  per base reads the base's latest checks. A PR whose failing check also fails on the base is held
  (nothing sent, nothing counted), and master is woken once per base episode. A base check still
  running makes the PR wait.
- **Silence is never "all green"**: a check that never finishes, a base that stays running or a
  base that cannot be read keeps the PR silent, its stop included. The loop's own failures show in
  the merge-queue health check's `ci` field.
- **`ci.loop`** (on by default; `AGENT_BUS_CI_LOOP=off` turns it off). GitHub with `gh` only:
  GitLab, Bitbucket and the local forge get no loop yet. A repository with no CI stays silent.

**busmon** (#613 spec, #614, #615, #616, #630):

- **Braille sparklines** (#614): the Tokens page's 7-day column follows `display.graphs`: `block`
  (eight blocks), `braille` (two days per cell), `ascii` (`_.-:=+*#`) or `auto`, the default: `ascii`
  when the locale does not name UTF-8, else `block`, never braille. Set on the `C` page or with
  `AGENT_BUS_BUSMON_GRAPHS`; it applies from the next frame. Gauges and bars keep their blocks.
- **The light theme reads on a dark terminal** (#615): `display.theme = light` paints its own
  white background on every cell. Each colour role keeps a minimum contrast in both themes (4.5:1
  for text, 3:1 for the rest but frame lines). Dim, the dark inactive tab and one agent colour were
  raised to meet it.
- **tcell removed** (#616): busmon keeps its colours in its own types, with the same look (the
  goldens are unchanged). `go.mod` drops `gdamore/tcell`, `gdamore/encoding` and `golang.org/x/text`.
- busmon's slowest test suite runs faster (#630).

**Files are written atomically** (#617): lifecycle records, quota state, `config.toml` and busmon's
cache go through one writer. It creates a missing directory as `0700` (an existing one keeps its
mode), writes a `0600` temporary file beside the target, syncs it, renames it into place and syncs
the directory. A crash leaves the old file or the new one, never half
of one.

**The escalation target reaches every check** (#621): under `agentbus service run dispatch
--escalate-to <agent>` (or `AGENT_BUS_ESCALATE_TO` in the project's env file), the stall checks,
self-repair and the reboot judge now escalate to that agent, as the loop already did. Before, they
still went to master. The foreground `agentbus dispatch --escalate-to` was not affected.

**The dispatch service's runtime is `internal/dispatchsvc`** (#618 spec
`docs/superpowers/specs/2026-11-19-dispatchsvc-extraction-design.md`, #619, #620, #623 to #629,
#632, #634, #635, #638, #643, #644): its health-check readers, stall checks, chores and reboot
judge left `cmd/agentbus` whole. Before that, the helpers moved to their packages unchanged (#623 to
#629, #632), the shared test fixtures moved (#634, #638) and the service's functions were gathered
in one file (#635). The move changes no behaviour, and both binaries keep their paths. A guard test
(`TestGuard`) keeps the package from importing the CLI or the screen, or from running a program not
on its list. The shared text helpers are one copy in `internal/textfmt` (#619, #620). #644 repoints
the notes' file paths.

**Specs and ideas, no code yet:**

- **A language setting** (#611, `docs/superpowers/specs/2026-11-18-language-setting-design.md`):
  French or English for what the person reads in busmon; the bus and the CLI stay English.
- **An idea** (#642): a turn lost without its Stop hook while work is open sends one notice to
  master. It waits for the person, to be built after the dispatchsvc move.
- **The v0.31 plan** (#640, `docs/plans/v0.31.json`): the work since v0.30.0 grouped into tasks
  with their PRs, and the open items. #612 added the v0.29.0 and v0.30.0 changelog entries.

**Upgrading:** run `./setup.sh update`. It names each project service still running an older build
and offers to restart it. The CI loop runs only once the project's dispatch service runs this
build. Answer yes, or run `agentbus --project <p> service restart dispatch` yourself. Holders and
agents are not touched. On a GitHub project, `gh` must be authenticated for the loop to run.

**Left out of this release** (open in the v0.31 plan, not merged into `dev` at `f018542c`):

- Timing the CI loop's reads (`gh pr list` with the checks, plus the base call) on a project with
  real checks (ci-loop spec §7, the person's check).
- The language setting's code, an agent's background work shown in busmon, and the views
  redesign's code (all three specified, not built).
- Restart buttons for the project's services in busmon.
- A rewrite of the README and the operations guide for the holder-hosted team.
- Moving the person's other projects to this release (the person's command).
