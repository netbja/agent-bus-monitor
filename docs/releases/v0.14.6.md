# v0.14.6 — a quota reset granted early is seen

## Fixed

- **hyperliquid stayed paused for 96 hours after Anthropic reset the quota.**
  - Without the statusline installed, the only Claude reading came from the transcript backstop:
    the last "weekly limit" refusal, with its announced reset on Monday.
  - When Anthropic granted a reset early, no new refusal appeared. The old one was believed until
    Monday, so the hold and the project pause stayed in place.
- **A refusal is now void once Claude has answered since,** in any session of the account. An
  answer is an assistant turn that is not a synthetic error; a synthetic error (another limit hit,
  an outage) proves nothing. A newer refusal holds again.
- **With no window to read, a recent answer ends the hold** (within the 30-minute freshness rule).
  For the coordinator's provider, the quota pause ends with it.
- **An early end of a quota pause now sends the resume directive** to the pause's notify target
  (master), in the same script as the delete, as a pause reaching its deadline already did. It
  used to end silently.
- **`agentbus quota` shows `served 2m ago`** for a provider whose reading has no window but whose
  last answer is known.

## Still recommended

Install the statusline (`agentbus statusline --print-install`): it gives the real percentages,
so the service warns and holds before a refusal instead of after it.
