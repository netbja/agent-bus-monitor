# v0.10.3 — quieter verdicts, a hardened launch cache

A small patch from what the roles-go missions and a security read turned up.

## What changes

- **`agentbus verdict` no longer cries wolf on mission reviews.** The conductor opens a mission
  review as a challenge on the *reviewer's* gate and closes it itself once it reads the verdict
  ledger. `verdict` only looked at the *author's* gate, so every mission verdict printed
  `notice: no open challenge`. Now it says
  `review "<ref>" is open on <reviewer> (…); the conductor closes it once it reads this verdict`
  and leaves that gate alone. The notice remains for a ref that is open nowhere (a typo or a
  stale ref).
- **The launch cache is trusted only for what it holds.** The cache holds Kimi's generated agent
  file and a custom adapter's spec, under `AGENT_LAUNCH_CACHE` or `~/.cache/agentbus/launch`.
  An entry used to be reused as soon as a file of that name existed, even a symlink, a behaviour
  inherited from the Python version. Now:
  - an entry is reused only if it is a regular file whose content matches the sha256 in its name;
    a symlink or a tampered file is replaced, and the rename never writes through a link;
  - a cache directory that others can write to (`chmod g+w` or `o+w`) is refused with a clear
    message, because anything planted there would become a client's prompt or spec.

  This was found by a partial security read from Grok, which ran out of quota before writing its
  report. The rest of that review is still to be done.

## Validation

Disposable Redis via `AGENTBUS_TEST_REDIS_URL=redis://127.0.0.1:6392`; the operational broker was
not used.

- `go build`, `go vet`, `go test ./... -race -count=1`, `bash tests/run.sh` and
  `agentbus mem check` pass.
- New tests, each seen failing before its fix:
  - `TestVerdictGateNotice`: a mission review, a classic gate on the author, an unknown ref;
  - `TestCacheFileReplacesTamperedEntries`: tampered content, and a symlink whose target is never
    written;
  - `TestCacheFileRefusesAWritableSharedDir`.
