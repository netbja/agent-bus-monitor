# v0.6.1 — tests stop reaching for the production broker

A test-only patch. **No executable code changed**: `git diff v0.6.0..v0.6.1`
touches three `_test.go` files, one test-only helper package, and documentation.
The binaries are byte-for-byte the same work as v0.6.0 — there is nothing to
redeploy, and the subscribe protocol stays at v1 with no wire change.

## What it fixes

`go test ./...` on a machine with the broker running connected to **that
broker**. Nothing said so, nothing asked, and the default port is the production
one. The suite cleaned up after itself, which is exactly why it went unnoticed.

Tests now opt in through `AGENTBUS_TEST_REDIS_URL`, and only through it:

- **unset** — every Redis case skips, whatever `REDIS_URL`, `REDIS_HOST` or the
  default port say. An ambient production URL cannot authorise a test
  connection, and the skip path leaves that ambient value untouched.
- **set** — it overrides the ambient configuration for the tests and for the
  subscriber child process, and an **unreachable** configured endpoint fails the
  suite instead of skipping it. A guard that silently skips when its endpoint is
  down teaches you to ignore it.

Three dial sites are covered — `bus.dialTest`, `agentbus.dialMain`, and the
subscriber child helper. The deadline probe reaches Redis only through
`dialTest`, so it is covered too; no test dials outside these.

## Validation

On a fresh disposable `redis:8-alpine` (`redis_version:8.6.3`, empty at start,
`127.0.0.1:6392`, removed afterwards) — never the configured broker on 6380:

| Run | Configuration | Result |
| --- | --- | --- |
| A | no opt-in, ambient `REDIS_URL=redis://production.invalid:6380` | 157 pass, **71 skip**, 0 fail, 5 packages |
| B | opt-in to the disposable Redis 8, same ambient URL | 227 pass, **1 skip**, 0 fail |
| C | opt-in to a dead endpoint, unix socket and tcp | **FAIL** — `explicit test Redis unavailable: …` |
| D | run B with `-race` | 227 pass, **1 skip**, 0 fail |

Counts include subtests; run A reproduces the 157/71 measured independently the
day before, which cross-checks the counting method. The one skip left in B and D
is `TestAmbientRedisDoesNotOptIn/requires_explicit_endpoint` — the intentional
guard probe, and nothing else. `go build ./...` and `go vet ./...` pass.

Checked from the other side as well: afterwards the configured broker still
listed only its five real projects, and a `SCAN` there for throwaway `t*:cmd`
test projects returned nothing.

## Limits

`AGENTBUS_TEST_REDIS_URL` is an operator **assertion** of isolation, not a
detection: nothing proves the endpoint someone supplies is disposable. The shell
suites were neither changed nor run. Reverting this patch restores the unsafe
default, so a revert is a decision about test safety, not a neutral rollback.

## Provenance

The guard was written and reviewed by Codex on 2026-09-19 but could not be
committed from its own sandbox — read-only Git index, plus a refused socket bind
that also blocked the integration run. It was carried across with the missing
validation and merged as PR #42.
