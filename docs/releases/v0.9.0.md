# v0.9.0 — busmon redesign

busmon now reads like a modern dashboard rather than a block terminal: a **btop-style table of
agents** sorted by what needs attention, Activity in columns, Board and Requests beside it, and
details one keypress away. It adapts to the terminal width, keeps every frame straight at every
size, follows the terminal's background (dark by default, `--theme light`), and honours
`NO_COLOR`. Nothing changes on the bus: `bus/`, `dispatch/` and `agentbus` are untouched.

## What changes

- **Agents table** — one row per agent, attention first (escalated, gated or blocked; then
  queued or being woken; then working, idle, done, never declared), names inside each group.
  Columns: declared state with glyph and word, a freshness bar that empties over 10 minutes
  (freshness, not liveness), the wake-eligible queue (`·` measured zero, `—` not measured yet,
  `N?` last read failed), the agent's own context in raw tokens, up to two flags in words
  (`escalated`, `escalating`, `gate N`, `deferred`, `unobserved`, `waking`, `woken`, `pilot`,
  `armed`, `stale N`) and the status message. The panel holds about a third of the screen and
  scrolls with a scrollbar on its border. Enter or a click opens the **agent detail**: full status
  message, pane and pid, lease, queue with the shared-stream lag and its caveat, wake record,
  possible gap, gates, context, board tasks and the agent's last activity lines.
- **Activity** in columns (`time · from · to · type · message`), one line per event, live until you
  move up; the title says `paused · N new` and keeps the filter visible.
- **Board** with column headers; **Requests** lists tracked requests still waiting and untracked
  threads, counted the same way as the header.
- **Header** — health and dispatch first and never truncated (`● bus ok` / `▲ bus down 42s`,
  `● dispatch up` / `○ dispatch down`), then project, pilot, waiting requests, the account budget
  **used** per provider as gauges, and the clock.
- **Responsive** — wide (≥ 120 columns), medium (80–119: tabs `1 Activity · 2 Board · 3 Requests`),
  narrow (< 80: one view at a time, `1 Agents · 2 Activity · 3 Board · 4 Req`), and a plain
  "terminal too small" under 30×6.
- **Keys** — focus starts on Agents. `Tab` / `Shift-Tab` move between panels, `↑↓ j k`, `PgUp/PgDn`,
  `Home/g`, `End/G` (on Activity: back to live), `Enter`/`v` or click open, `y` copies, `/` filters,
  `i` or `:` writes, `@` starts a directive, `F1`/`?` help, `F2`/`r` requests, `q` quits (not while
  typing), `Esc` steps back (selection, pause, filter) and never quits; a click outside an open
  detail closes it like `Esc`. The footer and the help (F1) are generated from the same key table
  as the handler, so every key is listed.
- **Theme** — colours are roles in one file; the terminal's background is kept; dark, light,
  16-colour and no-colour palettes. Every state is also a glyph and a word.
- **Alignment** — only single-cell glyphs are drawn; every width is measured by grapheme cluster;
  agent text is sanitised (tabs, newlines, escape sequences, bidi controls) for rows and kept
  byte-exact for copy. The retired badges `👂 ⌛ 🔒 ⧉ ⬢ ✉ ⏰ ⚠ ✂ old:N` became words; the v0.8
  known issues on `⌛N` and `✂?` leave the main screen (lag and gap live in the agent detail).

## Use it

`go build -o busmon ./cmd/busmon` (the bootstrap `busmon` tab runs `<repo>/busmon`), then
`busmon --project <p>` as before. `--theme light` or `AGENT_BUS_BUSMON_THEME=light` for a light
terminal. The box-drawing glyphs assume the terminal renders East-Asian "ambiguous" width as
narrow (the default in Western locales). Design: the
spec (`specs/2026-10-10-busmon-ui-redesign-design.md`, kept out of the repository) and
plan (`plans/2026-10-10-busmon-ui-redesign.md`, kept out of the repository).

## Validation

Branch `feat/v0.9-busmon-ui`, disposable Redis 8.6.3 via `AGENTBUS_TEST_REDIS_URL=redis://127.0.0.1:6392`;
the operational broker was not used.

- `go build ./...`, `go vet ./...`, `go test ./... -count=1 -race`: all packages pass.
- `TestAlignmentSuite` draws the real screen and every overlay at 13 sizes (160×45 down to 30×6),
  dark and no-colour, broker up and down, with hostile fixtures (20 agents, 32-char names, ZWJ
  emoji, CJK, combining accents, tabs, newlines, escape sequences, bidi controls, tag look-alikes),
  and checks every frame's corners and borders cell by cell; a deliberate one-cell overflow makes
  it fail.
- Application tests on a simulation screen: resize during an asynchronous thread read, too-small
  round trip with an overlay open, focus across tiers, Tab never reaching a hidden panel, the Esc
  ladder, separate message and filter drafts, modal overlay swallowing outside clicks, read
  inventory per tick, broker down keeps values.

## Limits

- The ACP/CLI drivers announced for v0.9 move to v0.10.
- Contrast is chosen, not measured: dim and line roles may fade on unusual backgrounds.
- When the selected Activity event is evicted from the 500-line window, the selection moves to the
  event now at its former position.
