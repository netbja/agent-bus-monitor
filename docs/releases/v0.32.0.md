# v0.32.0 — agentbus update, the views redesign, background work in busmon, and restart from busmon

This release gathers the 29 PRs merged into `dev` since v0.31.0, #647 to #679 (#656, #668, #672
and #675 were closed and replaced by later PRs). `dev` stood at `4293d002` when these notes were
written. `main` takes them as one promotion, on the person's yes. These notes are their own PR.
The person gets a command that updates agent-bus to the latest release, a redesigned Board, Plan
and Requests in busmon, background work shown beside each agent, and a restart key for the
services. What the release leaves out is listed at the end.

**`agentbus update`** (#654 spec, #659): installs the latest release with a snapshot to roll back
to. It is the person's command, built in its own tree, and does nothing to holders or agents.

- **Where it comes from.** The newest `vX.Y.Z` tag on the clone's `origin/main`. The tag is
  checked out as a worktree of the clone, `${XDG_DATA_HOME:-~/.local/share}/agentbus/src/<tag>`,
  and both binaries are built there. A moved or deleted clone is refused, with the path to put it
  back to.
- **What it refuses.** A `dev`, `-dirty` or diverged build, and a binary not built by setup. Each
  refusal names `./setup.sh update`, which stays the path for those builds.
- **What it changes, in order.** A snapshot of both binaries first, then `agentbus`, then
  `busmon`, the `agent-launch` link, the skills, and the dispatch and missions services of the
  project named by `--project`. Those two must record the new build within 60 seconds. On any
  failure it rolls back by itself.
- **What it never touches.** Holders, agents, the broker, `config.toml`, env files. Other
  projects' services are listed with the command to restart each.
- **Flags.** `--check` prints the plan only. `--rollback [<id>]` restores a snapshot (the last one
  by default). `--list` shows the snapshots; 3 are kept. An update killed midway is refused until
  `--rollback` has run. An agent is refused for everything but `--check` and `--list`.
- **No bus message.** Its record is the terminal and `<state>/agentbus/updates/history`.

**busmon: the views redesign** (#649 to #652, #660, #661, #665; spec
`docs/superpowers/specs/2026-11-17-views-redesign-design.md`):

- **The Board flags a late or lost request** (#651). One line per task, alerts first. An ALERT
  column appears only while a row has one: `no acceptance <age>` (past `board.no_accept_after`,
  default 30m), `no reply <age>` (past `board.no_reply_after`, default 2h), or `body lost`. Both
  settings are in the `C` page's Display group, `0` turns one off, and they apply at once. Done
  tasks are hidden until `d`. busmon changes no request itself: the frame names who acts.
- **One Requests view** (#652). `r` and `F2` open it from any tab, the Board included; the old
  read-only Requests page is gone. Esc, the tab bar and the arrows return to the tab you came
  from. Work's `between agents` line now opens the Board filtered to those rows.
- **The Plan is the fourth tab, a roadmap** (#660): NOW, APPROVED, NEXT, LATER and DONE, sorted by
  priority then file order. It is no longer an alias of Work's NEXT, and `p` opens the same
  roadmap as a drawer. A plan task may carry `"priority": "high"` or `"low"`.
- **The person sets a task's priority** (#661, #665). `+` and `-` on a plan task in busmon, or
  `agentbus plan priority <task> high|normal|low --as <person>`. The person's level wins over the
  plan file's, and an agent is refused. `request send` starts the request for that task at its
  level.
- **For you names the plan's decisions** (#650) instead of saying "Nothing expected from you."
  while some wait.
- **IDEAS lists the idea notes** (#649) of `docs/memory/open-questions/` beside the broker's ideas,
  when busmon runs where the project's checkout is.

**busmon: services** (#647 spec, #662, #664):

- **A readable log page** (#662). F3, Enter on a service card: a level per line, a dispatch
  decision as `action  agent  reason  (rule N)`, the routine `none` decisions folded (`a` shows
  them), `f` keeps the lines holding a word. The dispatcher now writes a time (`ts`) on each line it
  logs; older lines show none.
- **Restart a service with `X`** (#664). On the dispatch or missions card, busmon shows the exact
  command, `agentbus --project <p> service restart <kind>`, and `y` runs it as the person. It
  refuses in an agent's environment, for another host's service, for one not installed here and
  for the Redis card. Holders stay read-only.

**Background work is visible** (#658 spec, #666, #667, #674, #679):

- **Claude Code's hooks report it** (#666): the `Stop` list and the new `SubagentStop` list become
  `{p}:bgtasks:<agent>`, with types, statuses, sub-agent names and times, never a command or a
  prompt. It takes effect at an agent's next launch and the dispatcher's next restart.
- **The dispatcher counts processes** (#667): each agent's observation gains the number of its
  active non-helper descendants and the oldest one's start. No process name is published.
- **busmon shows one mark per agent** (#674), beside its message. The state word is unchanged: an
  agent with only background work still reads `idle`. The mark is the agent's declared text, else
  the hooks' tasks (`3 bg tasks 14m`), else the process count as a lower bound (`bg ≥1? 9m`); `◷`
  follows when it has scheduled wakeups. The agent's page gains a Background section.
- **One notice to the escalation target** (#679), when the dispatcher has skipped an agent's
  auto-clear or pop-retire for its background work for `dispatch.background_notice_after` (2h by
  default, `0` turns it off). It names the agent, the action and the source, once per episode. An
  agent's declared text now also holds the pop-retire and `holder drain` while it lasts.

**Smaller changes:**

- **A red CI mark in the merge queue** (#653). `agentbus merge-queue` marks an approved PR whose
  head's checks are red (`CI red: <checks>`, `ci_red` in `--json`), from the rollup the loop
  already reads. No mark does not mean green: there is none with `ci.loop` off, on a cut rollup,
  or under the git fallback. busmon does not show it yet.
- **`person.language`** (#671, spec #657). A setting registered in `config/keys.go`, `en` by
  default and opt-in (env `AGENT_BUS_PERSON_LANGUAGE`). Master's role skill reads it through
  `agentbus config`, and master writes to the person in that language: its reports to the person,
  the text of its questions, its pane. Everything between agents stays English, and so do the
  question's choice labels and the dispatcher's notices. An invalid value shows as `invalid` and
  resolves to `en`. The setting and the skill contain no translation code: master writes the
  words.
- **A French README and operations guide** (#655, #669). Both rewritten for the holder-hosted team,
  and the French copies are now translations of them, with no out-of-date notice. #670
  regenerates `docs/assets/busmon.png`.
- **Merge conflicts** (#673 spec, #677). Master's skill gains four scheduling rules (siblings in
  series, a move or rewrite alone, two settings PRs in parallel, no stacking). `rerere.enabled`
  is on in the shared repository; a replayed resolution stays unstaged for the agent to read and
  test.
- **Two test fixes.** `TestRunTestTimeoutKillsGroup` checks that the process is dead, not that it
  was reaped (#663). `TestConfigJSON` compares `agentbus config`'s rows with `config.Keys` with
  no literal count, so two settings PRs no longer collide (#676).

**Specs and notes:** the designs behind the code above (#647, #654, #657, #658, #673) and the
update's person variant note (#648). #678 is a design for person memory, with no code yet.

**Upgrading:** run `./setup.sh update`, as before. It names each project service still on an older
build and offers to restart it; answer yes, or run `agentbus --project <p> service restart
<kind>`. The background marks need the dispatch service on this build, and the hooks' tasks need
each Claude Code agent relaunched. From the next release on, `agentbus update` does it for a
release build. `person.language` changes nothing until you set it.

**Limits:**

- `agentbus update` refuses a `dev` build, so this release itself is installed with
  `./setup.sh update`.
- The update's rollback was not checked by hand on a Mac. The spec keeps that check, for the
  signature of a rolled-back binary, as a blocker (§6, §7).

**Left out of this release:**

- busmon does not show the red CI mark.
- No code for person memory (#678; its
  second round, #680, is open).
- The update's automatic mode and its removal of old trees (the quiet-update spec).
- Moving the person's other projects to this release (the person's command).
