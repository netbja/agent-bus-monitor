# v0.30.0 — a sturdier holder, quota drain per project, agents' screens, and the person never an agent

This release gathers the 21 PRs merged into `dev` since v0.29.0, #580 to #601 (#591 was closed,
its test merged as #594; #602 is these notes). It is the first release made
through the dev branch flow: every PR went to `dev`, and `main` took one promotion. Most of it
hardens the holder, which hosts every agent's terminal since the herdr exit, and closes the gaps
the person met on 17 November: the person listed and woken as an agent, an ask answered with every
recommended option, approved PRs not shown for the merge. What the release leaves out is listed at
the end.

**The holder survives crashes, restarts and reboots** (#581 spec
`docs/superpowers/specs/2026-11-17-holder-hardening-design.md`, #583, #584, #585, #586):

- **A dead holder is the person's** (#583): health `holder`'s fail goes to For you with
  `agentbus --project <p> service start holder`, and the desktop rings once per episode. The warn
  `holder_restarted` says how many agents wait and when the last comes back at self-repair's pace.
- **A restarted holder numbers its terminals on** (#583): it numbered from `t1` after every
  restart, so the relaunched master got the dead master's pane and self-repair refused it. The
  last number is now kept in `holder.<build>.terms`, and the endurance test (release gate) pins
  the recovery.
- **After a reboot, the dispatch service judges once** (#585, reboot-resume A): it reads
  `run.json`, records the verdict in `{p}:reboot` and restarts the team after an unplanned stop
  only when `services.unplanned_restart` is on (the default; off, the team is never restarted
  after an unplanned stop), self-repair is on, the holder answers within 2 minutes, the repository is intact
  (no `index.lock`, `git fsck` passes) and at most 3 such restarts happened in 24 hours
  (`services.unplanned_*`). Otherwise the project is suspended, and the person is told once per
  boot. With `services.start_at_login`, the current build's holder starts at login.
- **The holder contains its screen emulator** (#584, G1 part 1): each terminal's emulator runs in
  its own goroutine behind a bounded queue, so a slow or stuck emulator never stalls the terminal.
  A gap, a panic or 10 s without progress marks the screen `invalid` or `stuck`; the dispatcher
  then waits (no wake, `/clear` or submit), and the terminal is replaced with `agentbus reload`.
  Terminal queries (DA1, DA2, DSR) are still answered, once each.
- **A live check before a release** (#586): `agentbus check holder-restart` brings up a disposable
  project, kills its holder and times the restart, the relaunches and the wakes (about six minutes;
  `--clients fake` by default, no quota spent).

**Agents' screens, blocked agents and the holders after an update** (#589 spec
`docs/superpowers/specs/2026-11-17-agent-screen-blocked-design.md`, #592, #593, #595, #598, #599,
#600):

- **`agentbus screen <agent>`** (#593, #600) prints an agent's last screen text, read-only, through
  the project's holders, with a header naming the terminal, its build and the read time (`--json`:
  `agent, term, build, rows, lines, trusted, read_at`). Master, sentinel and the person may run
  it; escape sequences are dropped whole, and an untrusted screen prints nothing.
- **busmon reads `blocked`** (#598) for an agent whose client asks something in its terminal (a
  permission or limit menu): "blocked: waiting for an answer in its terminal". `waiting` now means
  only the agent's own question (a declared wait or an open ask). The agent's page shows the
  screen's last 6 non-blank lines, read live while the page is open; a line that looks like a
  credential is hidden.
- **A stuck screen rings the desktop once per episode** (#599): settled, read as neither ready,
  busy nor a known prompt, and unchanged for `dispatch.stuck_after` (default 3 minutes, `0` off).
  The ring says the screen has not changed and is not a prompt agentbus knows; no screen text is
  written to the bus.
- **The dispatch service starts its own build's holder** when none answers (#592), as `agentbus
  up` does; the older holders keep their agents until `agentbus holder drain` moves them.
- **`holder-behind`** (#595): when only an older build's holder answers, the state says so and
  names which builds host an agent, since a pop, relaunch or reload would fail; `waiting-holder`
  now means no holder answers at all.

**Quota thresholds per project, with a drain** (#587, quota settings step 2):

- Three thresholds: `dispatch.quota_warn` (85) warns master and tells agents with work to finish
  their step; the new `dispatch.quota_drain` drains the run (unset, it follows the warning);
  `dispatch.quota_hold` (95) holds the provider. `warn <= drain <= hold`, or the defaults apply.
- A project's own values live in `config.toml`, `[project.<name>.dispatch]`, above the project's
  env file, the machine keys and the defaults. The dispatch service re-reads them every minute
  without a restart; an unreadable or removed `config.toml` keeps the last values.
- Stored quota messages carry the absolute date (`resets Tue 17 Nov 13:59`). Deleting a project
  removes its table.

**The person is never an agent** (#580, #590, #594, #597):

- **The cause** (#590): `agentbus ask <agent>` names the asking agent; `agentbus ask <person>` run
  in master's terminal wrote the person into `{p}:agents` with master's terminal, so busmon listed
  them under Agents and the dispatcher woke and escalated them. `ask` and `status` now refuse the
  person's recorded name (`identity.as`) from another agent's terminal; an entry that borrows
  another agent's terminal is no agent to the dispatcher or busmon, and the dispatcher knows the
  person from `identity.as`, not only from the capped cmd stream. #594 adds a test.
- **An ask comes from an agent, an answer from the person** (#597): `agentbus ask` asks only as
  the caller itself; a person's name, an unknown name or another agent's is refused with
  `ask <your agent name>; the person is the one who answers`. `agentbus answer` is refused from
  any agent, `--as` included.
- **`anonymous` is nobody** (#580), as the person's identity too.
- A leftover entry from before this release is removed with `agentbus agents forget <person>
  --force`.

**Smaller changes:**

- **busmon's paste label** (#588): a multi-line paste reads `[Pasted #1: its first words…, 10
  lines]`, so two pastes can be told apart.
- **Another profile by name** (#582): a role's `alt_profiles` in `roles.toml` may be popped with
  `agentbus pop <role> --profile <p>`; the shipped manifest gives architect `claude-fable`
  (Fable, counted against the separate `7d-fable` window). Never a quota fallback.
- **The views redesign, specified** (#601,
  `docs/superpowers/specs/2026-11-17-views-redesign-design.md`): one question per view, Board and
  Requests merged, Plan as a roadmap with `↑`/`↓` priority, IDEAS triage. Spec only, no code yet.
- **Ideas as notes** (#596): eleven ideas waiting for the person are notes in
  `docs/memory/open-questions/`, listed in `docs/memory/IDEAS.md`. busmon's IDEAS section still
  lists the broker's ideas (`agentbus idea`) only.

**Upgrading:** run `agentbus up <project>` once after installing: it starts this build's holder
beside the old one without touching the agents (or let the dispatch service start it, #592), then
`agentbus holder drain` when the agents are idle. Remove a person's stray agent entry if busmon
lists the person under Agents.

**Left out of this release** (in review or decided, not merged into `dev` at `5ec6e134`):

- busmon's question panel answering the preselected option on Enter (the person's choice pending).
- A delivered PR shown for the merge within seconds, and deliver requiring both reviewers
  (merge-popup-setting).
- The views redesign's code (#601 is its spec).
- A request nobody can accept (its body lost to retention, or expired) closed by its target or
  sender (request-lost-body).
- Holder G1 part 2 (health `holder` on an invalid screen, `agentbus reload --replace-broken`).
