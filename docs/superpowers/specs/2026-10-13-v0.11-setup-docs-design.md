## 2. `setup.sh` (install.sh kept as an alias)

`setup.sh install [flags]` is today's installer plus the fixes below. `setup.sh uninstall [--yes]
[--purge]` and `setup.sh status` are new. `install.sh` becomes `exec setup.sh install "$@"`.

### 2.1 install

- **herdr-plus through herdr's own store.**
  - Plugin missing and `--install-herdr` given: run `herdr plugin install cloudmanic/herdr-plus
    --ref $HERDR_PLUS_REF --yes`.
  - Existing checkout at `HERDR_PLUS_PATH`: run `herdr plugin link <path>` instead.
  - Then check `herdr plugin action list` for `cloudmanic.herdr-plus.projects`. If it is missing,
    warn and print the exact command to run.
  - The `~/Tools` clone is no longer the default.
- **External skills.** Clone `mattpocock/skills` at a pinned ref into
  `${XDG_DATA_HOME:-~/.local/share}/agentbus/skills/mattpocock`. On a re-run, fetch and check out
  the ref again.
  - `rolecfg`'s default `POCOCK_SKILLS_ROOT` becomes that path. The old
    `~/Tools/herdr-plugins/skills/skills` stays as a fallback, so existing machines keep working.
  - `--no-skills` skips both the clone and the links.
- **A missing skill no longer stops an agent.** `agent-launch` prints
  `warning: skill <name> not found (run ./setup.sh install); <role> starts without it` and goes
  on. This is a deliberate break from the Python behaviour: a team that does not start is worse
  than an agent missing a convenience skill. `install-skills` still refuses to write a partial
  set of links.

### 2.2 uninstall (asks first; the default is cautious)

Each step is listed and confirmed. `--yes` accepts the cautious default at every step:

- the `agentbus` and `busmon` binaries in `BIN_DIR`, only if they are ours (`agentbus version`
  answers);
- the role-skill symlinks that point into this repository or the external skills folder, never
  a real directory;
- the herdr key binding block the installer added (backup first);
- the herdr-plus plugin (`herdr plugin uninstall`): asked separately, because herdr-plus is
  useful without agent-bus;
- the external skills folder;
- **Redis**: *stop it (keep the data)* / *remove the container and its data* / *leave it running*.
  `--yes` means stop. Only `--purge` removes the data without asking.

The repository and its built copies are left in place.

### 2.3 status

Prints, without changing anything:
- what is installed, and where;
- the binary versions and whether one shadows the other on `PATH`;
- whether herdr-plus is registered;
- the state of the skills folder;
- the state of the Redis container.

## 3. bootstrap: busmon first

The template writes the busmon tab first (focused on open), then the boot roles, then dispatch
and missions. `bootstrap new <p> --as <name>` puts `--as <name>` in the busmon command; without
it, busmon writes as `pilot`.

## 4. The docs agent

- **Role `docs`** (tier `pop`, skills `agent-bus` and a new `agent-bus-docs`). The skill says:
  - what to keep current: README, the operational guides EN/FR, the release notes, CHANGELOG.md,
    CLAUDE.md;
  - how to write: plain, sourced, no marketing;
  - how to deliver: a PR with a good-practice description (what, why, how it was validated,
    🤖 footer), reviewed through 4-eyes, **never merged by the agent**.
- **Triggered by `complete`.** `missions.json` gains an optional `"docs": "<agent>"`. When a
  change completes, the conductor sends that agent a directive through the same fenced write:
  `change <c> rev <n> complete on <branch>@<head>; update the docs and open the PR to <base>`.
  - The docs agent branches `pr/<change>` from that head, commits the documentation, pushes that
    branch (never `main`) and opens **the** PR to the base.
  - The conductor still never pushes.
  - If the docs agent is not running, the dispatcher escalates to master, and master pops it.
- master can also pop `docs` by hand for any doc task.

## 8. Added after review (user, 2026-10-13)

### 8.1 `setup.sh update`

- `git pull --ff-only` on the current branch; it refuses a dirty tree or a non-fast-forward.
- Then it rebuilds both binaries (repository and `BIN_DIR`), refreshes the external skills at
  their pinned ref and the herdr-plus plugin (`herdr plugin install … --ref`), and relinks the
  skills.
- It prints `vA → vB`, plus a link to CHANGELOG.md and to the release notes of each version in
  between.

### 8.2 A discreet update notice in busmon

- **The binary knows its version.** `setup.sh` builds with `-ldflags "-X …/buildinfo.Version=<git
  describe --tags>"`, and `agentbus version` and `busmon --version` print it. A plain `go build`
  says `dev`.
- **The check.**
  - It runs at most once every 24 h: a goroutine at startup calls
    `GET api.github.com/repos/netbja/agent-bus-monitor/releases/latest` with a 3 s timeout.
  - The result is cached in `${XDG_CACHE_HOME:-~/.cache}/agentbus/latest.json`.
  - A failure is silent and is not retried before the next day.
  - `AGENT_BUS_NO_UPDATE_CHECK=1` turns it off. A `dev` build never checks.
- **The display.** When the latest tag is newer than ours, the header gets `↑ vX.Y.Z` in the muted
  role. It is the lowest-priority header item: it is dropped first when space is short, never
  steals focus and is never a modal. The help mentions `./setup.sh update`.

### 8.3 `agentbus up <project> [<path>]` — one command, no picker

- **Provision.** If the project has no herdr-plus template yet, it provisions it (today's
  `bootstrap new`, with its flags passed through).
- **Open.** Inside herdr, it opens the workspace directly:
  `herdr workspace create --cwd <path> --label <project> --focus`. The first tab is busmon; then
  `herdr tab create` and `pane run` for each template tab, in order, the way herdr-plus opens a
  project.
- **Re-run.** On an already open workspace with the same label, it focuses it instead of opening
  a second one.
- **Outside herdr**, it provisions only, and says how to open the workspace (`herdr`, then
  `agentbus up <project>`, or the `Ctrl+B ↑` picker).
- The picker stays available to reopen projects.
- Tests use a fake `herdr` that records the calls (create, tabs in order, busmon first, focus on
  re-run).
