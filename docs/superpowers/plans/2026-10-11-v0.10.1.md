# v0.10.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.

**Goal:** let the dispatcher wake agents whose commands do not descend from their pane (Codex
app-server), by a bound identity; plus two mission minors (M1 brief path, M2 change complete).

**Architecture:** identity writes to `{p}:agents` go through one optimistic transaction
(WATCH/MULTI) shared by `status` and the new `bind`. `bind` validates a pid against herdr's
foreground set. The launcher binds itself before exec. The conductor detects a completed change,
reruns the suite, and writes the `complete` cmd and its marker in one fenced Lua script.

**Tech Stack:** Go 1.26, go-redis v9, herdr CLI, bash tests.

**Spec:** `docs/superpowers/specs/2026-10-11-v0.10.1-design.md`

## Global Constraints

- Tests never use the production broker: `AGENTBUS_TEST_REDIS_URL=redis://127.0.0.1:6392`.
- No new Python; the one-line launcher change in `scripts/lib/role_config.py` is the accepted exception.
- UI/CLI text in English. Every dispatcher/conductor write stays fenced.
- `subscribe` protocol stays `v:1`: the new cmd type `complete` is additive.

## Review Focus

1. A snapshot written by an older `status` racing a `bind` must not lose the bound identity.
2. `bind` with a pid that is in the pane but recycled (start time differs) → refused.
3. `complete` sent twice after a conductor restart between the suite run and the write.
4. A change whose missions are all skipped completes (suite still runs on the head).
5. Launcher bind failure must not stop the client from starting.

### Task 1: snapshot merge + `Bus.Bind` (bus/stream.go)

**Files:** Modify `bus/stream.go`; Test `bus/ident_merge_test.go` (unit: `mergeSnapshot`) and Redis case.

**Produces:** `func mergeSnapshot(old *AgentSnapshot, next AgentSnapshot, identityOnly bool) AgentSnapshot`;
`func (b *Bus) Bind(ctx, agent string, who AgentIdent) error`; `Bus.Status` uses `b.putSnapshot`.

Rules (`mergeSnapshot`):
- `identityOnly` (bind): result = old (or zero) with Pane/PID/PIDStart/Terminal from next.
- status, next.PID == 0 and old.PID > 0: keep old Pane/PID/PIDStart/Terminal.
- status, next.TS < old.TS: keep old State/Message/TS (identity still merged by the rules above).
- Session: next's if non-empty, else old's.

`putSnapshot` = `b.r.Watch(fn, AgentsKey)`: HGET, merge, TxPipelined HSET; retry up to 10 times on `redis.TxFailedErr`.

- [ ] Tests: `TestMergeKeepsVerifiedIdentity`, `TestMergeVerifiedReplaces`, `TestMergeOlderStatusDoesNotRegress`,
  `TestMergeBindKeepsState`, `TestBindThenStatusRedis` (Redis: bind then unverified status → pid kept).
- [ ] RED, implement, GREEN, commit `feat(bus): bound identity survives unverified status`.

### Task 3: `agentbus bind` (cmd/agentbus/bind.go)

**Produces:** `func runBind(ctx, b binder, lister procLister, args []string, env func(string) string, out io.Writer) (exit int, err error)`.
Usage: `bind <agent> [--pane <pane>] [--pid <pid>]`.
- pane: `--pane`, else `HERDR_PANE_ID` when `HERDR_ENV=1`, else error `bind: no pane (pass --pane)`.
- no `--pid`: print `PID PPID COMMAND` rows, exit 2, write nothing.
- `--pid` not in foreground set → error `pid N is not in the foreground of pane P`; else read
  `ProcStart`, call `Bus.Bind`, print `bound <agent> to <pane> pid <N>`.
- [ ] Tests with fake lister: no pid lists + exit 2 + no write; pid absent refused; good pid binds.
- [ ] Wire in `main.go` switch + usage text; commit.
